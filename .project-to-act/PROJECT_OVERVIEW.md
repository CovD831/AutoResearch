## 项目目标

- 以 LangGraph 搭建恰好五个业务 Agent 的 AutoResearch 系统：总控、论文搜索、论文读取、写作、审核。
- 覆盖 idea 拆解/深化、论文检索/总结/陪读、创新挖掘、工作包落实、论文写作/修改/润色的端到端闭环。
- 建立可审计证据库、分级证据策略、确定性门禁、状态机、结构化交接、固化工作流、Wiki+Graph 知识体系、用户画像、自进化提案和经验沉淀。
- 用 Project-to-Act 管理平台建设，并为每个论文项目提供独立、可验证的项目文件夹。
- 最终通过一个真实论文试点证明：关键 claim 可追溯、Gate 不可绕过、状态可恢复、交接不堆上下文、稿件不伪造引用或结果。

## 范围

### 包含

- Python/LangGraph 父图与五个 Agent 子图。
- 论文元数据检索、合规全文导入、去重、版本/撤稿/更正检查。
- 论文结构化阅读、阅读陪跑、claim-evidence、论文综合与创新候选。
- 工作包、实验/分析 RunManifest、artifact 版本和结果验证。
- 论文提纲、草稿、修订、润色、引用和格式导出。
- H/P/X/R 分级证据、证据包、L0–L4 风险门禁、人工 interrupt。
- 论文库、经验库、知识库、用户画像库、项目库、证据库的分区 Wiki+Graph 检索。
- 自进化问题/技巧归纳、复现、晋级、降级、灰度和回滚。
- Project-to-Act 论文项目模板、API/CLI/UI 入口、评测与审计。

### 非目标

- 不承诺研究 idea 必然新颖、实验必然成功或论文必然录用。
- 不把 LLM 推测、计划执行、模拟输出或静态文档写成真实实验结果。
- 不绕过付费墙、访问控制、版权许可或数据隐私边界。
- 默认不自动投稿、公开发布、发送外部消息、删除/覆盖原始资产或启动无上限高成本任务。
- 不让自进化直接修改门禁、权限、核心提示词、工作流或技能。
- 不将现有 `DeepReason-Agents-Framework` 的 14 Agent AutoResearch 模板原样视为目标实现。

## 技术路线与关键约束

- 运行时：LangGraph `StateGraph` 父图 + 恰好五个业务 Agent subgraph；服务节点不计为 Agent。
- 持久化：开发期 SQLite，正式环境 PostgreSQL checkpointer；跨线程长期数据使用 Store/项目服务。
- 数据：PostgreSQL 规范源 + pgvector + Neo4j 派生图索引 + 受控对象存储。
- 交接：只传 `HandoffEnvelope`/`HandoffResult` 和稳定 ID，不传完整聊天或全文。
- 门禁：确定性 fail-closed；LLM 只能产出审核建议，不能覆盖策略。
- 自进化：proposal-only；验证、审核、人工批准、灰度和回滚后才能晋级。
- 项目治理：根 `.project-to-act` 是平台目标/范围/进度/功能/版本/验收唯一事实源；每个论文子项目拥有独立账本。
- 详细架构：`docs/AutoResearch_详细计划书.md`。

## 数据与安全边界

- 数据分类：公开论文元数据、许可全文、用户授权研究资料、项目私有数据、用户画像、实验 artifact、审计日志。
- 敏感信息处理：只记录脱敏摘要、证据 ID 和受控位置，不粘贴原始敏感数据。
- 密钥与 provider 配置只允许来自环境或安全配置，禁止进入源码、项目文件、证据或记忆。
- 全文只处理开放获取或用户有权提供的副本；证据库优先保存 locator/hash/许可而不是复制正文。
- 用户画像按最小化、可见、可修改、可停用和可删除原则管理。
