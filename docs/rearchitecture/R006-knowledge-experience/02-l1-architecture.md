## 1. 分层

```text
┌─────────────────────────────────────────────────────────────┐
│  L5 回流层  ExperienceRecall                                 │
│     ├─ 事实通道（evidence）：带引用，可进论断                  │
│     └─ 经验通道（guidance）：experiential 标注，禁入事实声明    │
│  L4 画像层  ProfileService（三层 + 敏感信息禁 embedding）       │
│  L3 经验层  ExperienceService（X0→X4 阶梯 + 适用/不适用边界）   │
│  L2 检索层  RetrievalPipeline（L1–L5 + L8，按语料分层融合）     │
│  L1 地基层  KnowledgeStore（唯一写入者 + 页级 revision +        │
│             statement 级证据绑定 + 受管跨分区桥接边）            │
└─────────────────────────────────────────────────────────────┘
```

**依赖方向**：L5 → L4/L3 → L2 → L1。**不允许反向依赖**。

## 2. L1 地基层：`KnowledgeStore`

**唯一写入者**（对齐 R-004 的"唯一写入者"纪律）。

### 2.1 职责

| 职责 | 说明 |
|---|---|
| **唯一写入者** | 所有 `WikiPage` / `Statement` / `GraphEdge` 的写入必须经此层 |
| **页级 revision** | 每次改动生成新 revision，**不可覆盖**（append-only） |
| **statement 级证据绑定** | 页内每条知识声称独立绑定 `evidence_ids`，可独立失效 |
| **受管跨分区桥接** | 默认同分区边；跨分区边必须使用**受管桥接类型** |
| **分区分库** | 六个逻辑库（证据/项目/论文/经验/知识/画像）不混索引 |

### 2.2 不变量

1. **不可覆盖**：任何对已有 revision 的修改都产生**新 revision**，旧 revision 永存。
2. **跨分区受管**：跨分区边**必须**是受管桥接类型（见 §2.3），否则拒收。
3. **证据可追溯**：每条 statement 的 `evidence_ids` 可解析；**证据失效时 statement 状态降级而非删除**。
4. **分区隔离**：检索默认单分区；跨分区综合需**显式**声明（对齐 `KNOWLEDGE_AND_EVOLUTION.md:15`）。

### 2.3 跨分区边：从「全禁」收窄为「受管桥接」

**原禁令**（`knowledge.py:41-42`）的意图是「**防止一个经验页被伪装成论文证据**」—— 防的是**伪装**，不是**关联**。

**修正后**：

| 类别 | 处置 | 理由 |
|---|---|---|
| 无类型的任意跨分区边 | **禁止** | 这是原禁令要防的（可伪装） |
| **受管桥接类型**（下表） | **允许**，由 schema 校验 | 边类型本身声明语义（`REFERENCE` ≠ `EQUIVALENT`） |

**受管桥接类型白名单**（首批，可经注册表扩展）：

| 边类型 | 语义 | 典型跨库 |
|---|---|---|
| `CITES` | A 引用 B | 论文 → 论文 |
| `DERIVED_FROM` | A 派生自 B | 知识 → 论文 |
| `SUPPORTS` / `CONTRADICTS` | 证据关系 | 论文 → 证据 |
| `APPLIES_TO` | 经验适用于 | 经验 → 方法 |
| `SUPERSEDES` / `INVALIDATES` | 版本关系 | 同类型跨版本 |

**关键约束**：桥接边**不传递等价性**。`Experience --APPLIES_TO--> Method` 不意味着该经验是该方法的事实依据。

### 2.4 类型系统：**枚举核心 + 注册表扩展**

| 层 | 内容 | 演进方式 |
|---|---|---|
| **核心枚举** | 节点：`Paper`/`Claim`/`Method`/`Dataset`/`Metric`/`Experience`/`Decision`/`Concept`；边：§2.3 白名单 | 改代码（稳定，变更少） |
| **扩展注册表** | 其余类型 | **不改代码**，走注册表 + 版本化 |

**依据**：OpenAlex（受控词表 + 标准化标签）、PROV-O（核心少量类 + `specializationOf` 扩展）。

先做**枚举**，注册表留接口 —— 避免"硬编码枚举的演进成本"，也避免一开始就上完整注册表的过度设计。

## 3. L2 检索层：`RetrievalPipeline`

### 3.1 分级（对齐原设计 §13，本 program 做 L1–L5 + L8）

| 级 | 内容 | 本 program | 说明 |
|---|---|---|---|
| L0 | 权限与范围过滤 | **做** | project / partition |
| L1 | 精确召回 | **做** | DOI / hash / ID 精确匹配 |
| L2 | 词法 FTS | **做** | 替换现有朴素子串匹配 |
| L3 | 语义向量 | **做** | 按库独立索引（**禁止混索引**，对齐 §13 原文） |
| L4 | 图扩展 | **已有** | 现 `knowledge.py:85-101` |
| L5 | 融合 + rerank | **做，但分层**（见 §3.2） | 保留分数分解 |
| L6 | 证据过滤 | **不做**（后续） | — |
| L7 | ContextPack | **不做**（后续） | — |
| L8 | **召回审计** | **做** | **必须早做**：无它无法度量经验复用效果 |

### 3.2 融合策略：**按语料分层**（调研修正 2）

| 语料 | 规模 | 融合方式 | 理由 |
|---|---|---|---|
| **论文证据** | 大（数百~数千） | **L5 RRF**（k=60） | 两路信号正交，RRF 增值（Cormack 2009） |
| **经验 / 画像 / 知识** | 小（几十~几百） | **向量 + 适用条件字段过滤**，不套 RRF | 小语料两路高度相关，RRF 收益有限甚至为负 |

**关键判据**：**RRF 只在两路信号正交时增值**。小语料下词法与向量排序常高度相关。

### 3.3 L8 召回审计（必须）

每次召回记录：**查询、过滤器、候选、去重、重排、最终引用**。用途：
- 离线评测（对齐原设计 L8）
- **度量"经验复用是否让生产变好"** ← 本 program 的核心指标

## 4. L3 经验层：`ExperienceService`

### 4.1 成熟度阶梯（对齐原设计 §15）

```
问题 / 技巧 / 打回 / 失败事件
  → X0 原始候选
  → 去敏 + 归因 + 【适用边界】
  → 沙箱复现与回归
  → X2 已复现经验
  → 跨任务验证 + 反例
  → X3 跨项目经验
  → 变更提案
  → 审核 + 人工批准
  → 灰度 canary
  → X4 正式策略 ／ 失败回滚
```

### 4.2 加固项（调研修正 1，原设计未明说但实证要求）

| 加固 | 说明 | 依据 |
|---|---|---|
| **时效衰减** | 经验带 `valid_from` / `valid_until`；过期经验降权 | *When Memory Lies*：信过期记忆失败率 74.4% vs 无记忆 28% |
| **冲突消解** | 新证据与旧经验冲突时触发重审，**不静默覆盖** | `arXiv 2605.12978` |
| **反例抑制** | 检索到反例时**降低**对经验的采纳 | De Neys 2003：每多一个反例，规则接受度线性下降 |
| **raw 轨迹回链** | 抽象经验必须保留指向原始轨迹的引用 | `arXiv 2605.12978`：抽象会剥离适用条件 |

### 4.3 适用/不适用边界（**差异化机会**）

调研结论：**未找到"把显式适用条件作为可检索字段"的成熟生产系统**。

→ **applicability condition 必须作为独立可检索字段落库**，且**在 X1（去敏归因）阶段就结构化**，否则会被后续抽象步骤丢弃。

**这可能是本 program 相对业界领先的一处。**

## 6. L5 回流层：`ExperienceRecall`（**双通道**）

### 6.1 通道分离（**架构意图，非代码级强制**）

> **⚠️ 诚实声明**（经独立审查修正）：本机制**不是**代码级强制。
> 调研依据 *Grounding is not a prompt* 的论点恰恰是「**推理时 RAG 无法从结构上阻止模型把上下文当事实**」。
> 因此「双通道」是**提示结构**，**不是**能阻止 LLM 误用的机制。LLM 仍可能把经验当事实。
> **不得**在文档或验收中声称「双通道保证了 I1」。

| 通道 | 内容 | 进入位置 | 约束 |
|---|---|---|---|
| **事实通道** | 检索 / 实验结果，带引用 | system prompt 的 `evidence` 段 | **可进入论断**；受 R-004 的 grounding 约束 |
| **经验通道** | 历史经验（带 tier + 适用边界 + 反例） | system prompt 的 `guidance` 段 | 标注 `experiential`；**设计上禁入事实声明**（**但无技术强制**） |

**补偿措施（放在输出侧，而非输入侧）**：

既然提示层不可强制，补偿只能放在**可机械校验的输出侧** ——

> **论断必须能追溯到 `evidence` 通道的引用；追溯不到即拒绝。**

这是 R-004 门禁的**既有能力**（`gates.py` / `evidence.py` 的 claim-evidence 绑定），**复用而非新建**。

**这改变了 I1 的性质**：从「靠输入分离来保证」改为「**靠输出校验来兜底**」。

### 6.2 与 R-004 的接口

- R-004 的 agent **不感知**具体实现
- 通过**可选端口** `experience_port` 注入
- **无该端口时行为不变**（R-004 的既有测试全部保持绿色）

### 6.3 成熟度门控：**乘数 + 地板**（调研建议）

```
score = sim × tier_weight × recency
另设 MIN_TRUSTED_SCORE 地板
低成熟度经验：可因高相关浮现，但禁入事实通道
```

## 7. 不变量（全 program 级）

**分级说明**（经独立审查修正）：不变量分两类，**不得混称**。

| 级别 | 含义 | 可机械校验 |
|---|---|---|
| **硬不变量** | 有代码级强制手段 | ✅ |
| **架构意图** | 只有设计约定，**无技术强制** | ❌ 需如实标注 |

| # | 内容 | 级别 | 强制手段 / 如实说明 |
|---|---|---|---|
| I1 | **经验只能帮助选择流程，不能替代论文或实验事实** | **架构意图**（**非硬不变量**） | **无输入侧技术强制** —— 双通道是提示结构，LLM 仍可能误用（*Grounding is not a prompt*）。**补偿在输出侧**：论断必须可追溯到 `evidence` 通道引用（复用 R-004 门禁） |
| I2 | **Wiki revision 不可覆盖** | 硬不变量 | 新写入者以 append-only 写入。**前提**：现有 `storage.put` 是 `ON CONFLICT DO UPDATE`（upsert 覆盖写），**必须换写入者才能成立** |
| I3 | **跨分区边必须受管**（类型声明语义） | 硬不变量 | 边类型白名单 schema 校验 |
| I4 | **向量索引按库独立**，禁混索引 | 硬不变量 | 索引配置 |
| I5 | **证据失效 → statement 降级，不删除** | 硬不变量（部分） | "不删除"可校验；**"降级"语义需先定义**（见 §7.1） |
| I6 | **抽象经验必须保留 raw 轨迹回链** | **架构意图** | 无技术强制，靠 `ExperienceRecord` 必含字段 + code review |
| I7 | **评估集与阈值独立于自进化流程** | **架构意图** | 需治理层保证，无技术强制 |

### 7.1 决策 4 张力的裁决（经独立审查指出）

独立审查指出：**I2（不可覆盖）与 I5（证据失效时 statement 降级）存在张力** —— 若每次状态翻转都开新 page revision，则写入放大；若直接改 `statement.status`，则 statement 层可变，与 I2 精神冲突。

**裁决：两者正交，不冲突。**

| 层 | 管什么 | 变更方式 |
|---|---|---|
| **Page revision** | **知识内容**（title / body / statement 集合） | **append-only**，内容变则新 revision |
| **Statement status** | **证据有效性**（`supported` / `contradicted` / `needs_review`） | **就地更新**，是**元数据**不是内容 |

**关键澄清**：statement 状态翻转**不产生新 page revision** —— 它不是知识内容的变化，而是"该声称当前是否有证据支撑"的状态。这与 I2 不矛盾（I2 保护的是**内容历史**）。

**依据**：Graphiti / Zep 的 bitemporal 模型 —— 事实失效时置 `invalid_at` 而非删除；PROV-O 的 `wasInvalidatedBy` 同属元数据层。

## 9. 风险清单（钢人论证 B5 的产出）

| # | 风险 | 性质 | 处置 |
|---|---|---|---|
| R1 | **「适用条件作为可检索字段」无基线可对比** | 调研明说**无成熟先例** | 我们做出来属领先，但**无法证明它比不做更好**。→ 2026-09-15 修订：**不再用对照实验度量**；改由**沙箱复现**（该条件字段能否在适用场景命中、在不适用场景不命中）验证。无外部基线一事**如实声明** |
| R2 | **「反例抑制」是跨域移植** | De Neys 2003 是**人类条件推理**研究，移植到 LLM agent **无直接证据** | 作为**探索项**，不作为既定设计；契约里字段保留，生效机制待沙箱复现验证 |
| R3 | **I6（抽象经验保留 raw 回链）无法机械校验** | 约定级不变量 | 只能靠 code review + 抽查 |
| R4 | **I7（评估集独立于自进化流程）无法机械校验** | 约定级不变量 | 需在治理层保证 |
| R5 | **经验注入可能无收益甚至负收益** | 调研有**倒 U 与中毒实证**（Experience-Following：无过滤 Add-all **自降级**） | → **由回归集 + 灰度 + 回滚回答**（原 §15 机制）。回归集就是那个"过滤"的工程实现 |
| R6 | **`knowledge` 写入者重写会与既有调用方语义漂移** | 12 个调用点的既有行为需逐一对齐 | 适配器模式（决策 1）已把改动面降到 0，但**语义等价性需逐调用点验证** |

**约定级不变量（R3/R4）的处理原则**：如实标注，**不假装它们能被自动保证**。这是本项目反复教训（"文档声称 vs 实现"缺陷族）。

### 11.4 决策 1 的**理由更正**（经独立审查）

原表述：「原地扩展会让 revision 退化成可选字段」—— **不准确**。

**更正后**：底层 `store.put` 是 **upsert 覆盖写**，**不改写入者则 revision 根本不存在**（不是"退化"，是"不存在"）。

→ 这**强化了决策 1 的必要性**，但理由不同：不是"防退化"，而是"**底层语义与 append-only 不兼容，必须换写入者**"。

### 11.5 对执行顺序的影响

**既有机制的存在改变了工作性质**：

| 原以为 | 实际 |
|---|---|
| L2 检索层要**从零建** | 已有 L1（词法）+ L4（图扩展）骨架，**是升级不是新建** |
| X0→X4 阶梯要**从零建** | 已有 `record` + `promote` + 四门槛，**是补中间环节** |
| 唯一写入者是**新增约束** | 已有 6 个生产写入点，**是收拢而非新建** |

→ **工作量比原估算小**，且**冲突面比原估算大**（要在既有代码上改，不是另起炉灶）。
