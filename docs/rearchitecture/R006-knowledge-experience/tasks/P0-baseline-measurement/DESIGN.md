# P0 — 基线测量（本 program 的**止损点**）

**包 ID**：`R006-P0-BASELINE`
**性质**：**判据包**（决定本 program 是否继续，不产出功能）
**前置**：无（本 program 第一个包）
**裁决来源**：独立审查 F6/F2 —— 「整个 L1–L5+L8 的核心前提『积累让生产变好』被文档自引研究否定；L8 无法在前提为负时挽救」

---

## 1. 为什么 P0 必须最先做

**本 program 的全部投入建立在一个未验证的前提上**：

> 「积累经验 → 下次生产变好」

而调研（`01-external-research.md` §一）给出的是**反向证据**：

| 实证 | 数字 |
|---|---|
| LLM 抽象经验时剥离适用条件 | WebShop **0.64 → 0.20**（128 条后**劣于无记忆**） |
| 盲目信过期记忆 | 失败率 **74.4%** vs 无记忆 **28%** |
| 连续 consolidated memory | **倒 U**；折叠后失败率 54% |

**这些是别人的场景。我们的场景不同**（多 agent 论文生产 + 已有证据门禁 + `recurrence_count` 是派生值）。

→ **「这些失效模式会发生在我们身上」是推断，不是实测。** 先测。

**若 P0 结论为负或零 → 本 program 终止，不投入 P1 及以后。**

---

## 2. 测什么（单变量对照）

复用既有 `TrustBenchmarkRuntime`（A5 交付，1774 行），**不新建评测框架**。

### 2.1 对照条件

既有四条件（`BenchmarkCondition`）：

| 条件 | 含义 |
|---|---|
| `bare_llm` | 裸 LLM |
| `gate_off` | AutoResearch，门禁关 |
| `gate_on` | AutoResearch，门禁开 |
| （第四）`gate_on + recovery/replay` | 见 `docs/BENCHMARK.md` |

**P0 增加两个条件**（这是本包唯一的代码改动）：

| 新条件 | 含义 |
|---|---|
| `experience_off` | AutoResearch + 门禁开 + **不注入经验** |
| `experience_on` | AutoResearch + 门禁开 + **注入经验** |

**唯一变量** = 是否注入经验。其余（模型 / prompt / 材料 / 预算 / 随机种子）**全部固定**。

### 2.2 注入点

`BenchmarkAgent.draft(task)` 是既有协议（`benchmark.py`）。**P0 不改它**，只提供两个实现：

- `NoExperienceAgent` —— 不查经验（基线）
- `ExperienceAgent` —— 查经验并注入 `guidance` 段

**两个实现的其余代码路径必须完全相同**（同一次 LLM 调用、同一 prompt 模板、同一材料），差异**仅在于是否附加经验文本**。

### 2.3 经验来源（**折中方案：离线 + 噪声分层**）

**owner 裁决（2026-09-15）**：走「**(a) 纯离线 + 噪声分层**」，不走需要真实经验库的 (b)。

| 层 | 经验来源 | 目的 |
|---|---|---|
| **L-clean** | **同源合成**（由同一 `experience_sink` 管线从构造的审计事件生成，**非手写**） | 验证机制在理想条件下是否有效 |
| **L-noisy** | 同源合成 **+ 注入真实噪声**（模糊表述 / 含冲突经验 / 含过期经验） | 探 (b) 的风险：结论是否在噪声下稳健 |

**为什么这样做**：
- P0 验证的是**机制**（注入经验是否有用），不是**数据质量**
- 但合成经验可能"太干净" → **若 L-clean 正收益而 L-noisy 负收益，说明结论不稳健**，此时不得据此继续投 P1

**硬约束**：
- **禁止手写"看起来有用的经验"** —— 那测的是我们的想象，不是系统
- 三层经验（clean / noisy / wrong）**必须都由同一管线生成**，差异只在注入的输入
- 合成管线的构造参数（审计事件）**必须记录并可复现**

### 2.4 三层对照（L-clean / L-noisy / L-wrong）

| 条件 | 注入内容 | 是否参与止损判据 |
|---|---|---|
| `experience_off` | 无 | ✅ 基线 |
| `experience_clean` | 干净经验 | ✅ |
| `experience_noisy` | 含噪声经验 | ✅ |
| `experience_wrong` | 故意错误经验 | ❌ **探索性**（除非 clean 已正收益）

## 3. 止损判据（**必须在跑之前冻结**）

> **这一节是本包的核心。判据必须在测量前写死，否则事后解释空间太大。**

主指标取自既有 `paper` family（`docs/BENCHMARK.md`）：

| 指标 | 来源 |
|---|---|
| `claim_evidence_consistency` | claim–evidence 一致性 |
| `citation_locatability` | 引用可定位率 |
| `result_binding_rate` | 结果/数值绑定率 |

**P0 的判据**（主指标 `hallucination_ratio`，`lower_is_better`，同条件跑 3 次）：

| 结论 | 条件 |
|---|---|
| **继续（稳健正收益）** | `experience_clean` **< `experience_off`**（主指标更低）**且** 区间不重叠 **且** `experience_noisy` **也不劣于** `experience_off` |
| **终止（无收益）** | 主指标**无显著差异** |
| **终止（负收益）** | `experience_clean` **> `experience_off`** —— 直接终止，**记录为负向结果** |
| **终止（不稳健）** | clean 正收益但 **noisy 明显劣化** —— 说明结论只成立于理想输入，**不得据此投 P1** |

> **「不稳健」是独立于「无收益」的终止条件**，这是折中方案的核心：它用离线手段探到了 (b) 的风险。

**附加必查项（无论主指标如何）**：

| 检查 | 为什么 |
|---|---|
| **`unsupported_claim` / `hallucination_ratio` 是否上升** | 验证引用研究：经验是否被当成事实引用（I1 的实际检验） |
| **`acceptance_rate` 是否异常** | 若经验注入导致更多内容被拒，是隐性代价 |
| **同条件 3 次跑的方差** | 单次结果不足以判定 |
| **样本量** | 报告 case 数与置信区间（对齐 `docs/BENCHMARK.md`） |
| **`planned` / `unavailable` 计数** | 对齐既有纪律：不得把未观测当成观测（防"空集当满分"） |

## 4. 反事实鲁棒性（调研建议，本包作为**实验项**）

调研建议：**注入"语义相似但错误"的经验，验证 agent 不盲从**（参考 RAGenEval 的 CounterfactualRobustness）。

| 条件 | 含义 |
|---|---|
| `experience_wrong` | 注入**故意错误**的经验 |

**注意**：此条为**探索性**，**不作为 P0 的止损判据**（除非 `experience_on` 已显示正收益）。

理由：反例抑制的移植依据（De Neys 2003）是**人类条件推理**研究，**无 LLM agent 直接证据**（风险清单 R2）。

---

## 5. 明确不做的事（范围纪律）

| 不做 | 为什么 |
|---|---|
| ❌ 不做向量检索 | P0 只用**最简单的经验检索**（关键词/全量），够验证前提即可 |
| ❌ 不做 RRF / 融合 | 前提未证，融合是优化 |
| ❌ 不做 L8 召回审计 | L8 是基础设施，P0 之后才需要 |
| ❌ 不做 revision / 知识体系改造 | 与「经验有没有用」无关 |
| ❌ 不建新评测框架 | **复用 `TrustBenchmarkRuntime`** |

> **若 P0 发现"检索质量是瓶颈"**，那才是 L3 的证据 —— 而不是先建 L3 再假设它有用。

## 7. 风险与如实声明

| 风险 | 处置 |
|---|---|
| 真实经验样本不足（`experiences` 库可能是空的） | 记录事实；用**同源合成**补充；**不手写** |
| 主指标对"经验有没有用"不敏感 | **P0 的失败也是一种结论** —— 说明现有指标测不出这个效应，需先改指标 |
| LLM 调用成本 | 用预算控制（既有 `ResourceBudget`） |
| 结论可能"既不显著为正也不为负" | 按判据表 → **终止**（不投入未证前提） |

---

## 8. 为什么这是「最小迭代闭环」

```
经验库（已有 A6 产物）
   ↓ 简单检索（不做向量）
注入 agent 上下文（guidance 段）
   ↓ 跑对照
主指标对比 → 结论
```

**一环不缺，一环不多。** 它验证的正是本 program 的核心前提，而**不含任何为后续包预留的架构**。

若它通过 → P1/P2 有了依据；若不通过 → 省下整个 program 的投入。
