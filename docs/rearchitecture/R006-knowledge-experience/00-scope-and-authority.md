## 1. 为什么这不是重构

R-004 是**重构**，因为原始论文生成管线不好，需要改造（做薄 Runtime、抽出可插拔 Capability、独立信任层）。

R-006 覆盖的领域**原始设计是好的**，问题是**从未按设计实现**。原设计文档 §12–§15 给出了完整的知识体系、分级检索、用户画像与自进化方案，而当前实现只做到骨架：

| 领域 | 原始设计 | 当前实现 | 差距性质 |
|---|---|---|---|
| §12 知识体系 | 六库 + Wiki 不可覆盖 revision + 图谱类型系统 | 5 分区；`WikiPage` 无 revision/作者/审核状态；`GraphEdge.relation` 是无约束字符串 | **未实现** |
| §13 分级检索 | L0–L8 九级管线 | 只有 L4（图扩展）；`knowledge.py` 共 119 行 | **未实现** |
| §14 用户画像 | 三层（explicit/inferred/confirmed）+ 敏感信息禁 embedding | 有 `confidence`/`confirmed_by_user` 字段，无三层枚举、无脱敏策略 | **部分** |
| §15 自进化 | X0→X2→X3→X4 成熟度阶梯 + 适用/不适用边界 + 沙箱复现 + 灰度回滚 | 只到 X0（`experience_sink.py` 从审计事件生成失败经验） | **未实现** |

**结论**：R-006 是「**按设计实现**」，交付物是把 §12–§15 从未实现变为已实现。因此本 program 的文档重心在 **契约定义与不变量**，而非"改造方案"。

**佐证**：R-004 显式排除过这一块 ——
> `00-scope-and-authority.md:31`「**不在 S1–S4 内做检索/阅读/写作算法本身的科研质量提升（它们是可替换能力）**」

且 R-004 的「唯一写入者」表（`02-l1-target-architecture.md:49-62`）**不含** `WikiPage` / `ExperienceRecord` / `EvolutionProposal` / `UserProfileItem` —— 这些事实在 R-004 的边界之外。

## 2. 本 program 的目标

**一句话**：让论文生产**因为积累而变得更好**。

具体地，把这条链闭上：

```
论文生产 ──① 轨迹/失败──> 经验沉淀 ──② 成熟度阶梯──> 可复用的经验
    ↑                                                      │
    └──────── ④ 回流：agent 开工时查经验 <── ③ 分级检索 ────┘
```

**当前断点**：①②部分存在（A6 做了 X0），**③④完全缺失**。经验积累后被记录，然后**躺在库里**——**5 个 agent（orchestrator / paper_search / paper_reader / writer / reviewer）无一调用 `knowledge.retrieve`**（实测：`src/autoresearch/agents/` 下 0 处引用）。

## 4. 四条已定决策（owner 2026-09-14）

### 决策 1：地基层**重写写入者**，**以适配器模式**（0 调用点改动）

**改动面实测**（2026-09-14，含测试）：

| 接口 | 生产调用点 | 测试调用点 | 合计 |
|---|---|---|---|
| `knowledge.add_page` | **6**（`api:133` / `evolution_service:27` / `profile_service:22` / `reader_service:135,207` / `search_service:141`） | 3（`test_governance_services:115,124,133`） | **9** |
| `knowledge.add_edge` | **1**（`reader_service:151`） | 2（`test_governance_services:141,151`） | **3** |

> 注：`agents/base.py:42-43` 与 `graph.py:198-218` 的 `builder.add_edge` 是 **langgraph 的图构造**，与 `knowledge.add_edge` 无关，不计入。

**方案（经钢人论证修正）**：

- **保留 `add_page(page)` / `add_edge(edge)` 签名**，内部委托给新的 revision 写入者
- **12 个调用点一个都不用改**
- revision 仍是**强制**的 —— 因为唯一入口就是新写入者

**为什么这比"改所有调用点"更好**（钢人论证立场 B 的产出）：
- 「重写写入者」与「改调用点」是**两件事**，原方案把二者绑定
- 后者会让写入者重写成为**所有包的串行前置** —— 与「尽可能并行开发」的目标直接冲突
- 适配器模式下，其余包可在**写入者契约冻结后立即并行**

**理由**：「不可覆盖」是 §12 的**核心不变量**，不是可选功能。原地扩展会让它变成"调用方记得填才有效"的软约束；适配器模式则在**不改调用方**的前提下保持强制。

### 决策 2：检索管线做 **L1–L5 + L8**（跳过 L6/L7）

- L1 精确召回 / L2 词法 FTS / L3 语义向量 / L4 图扩展（已有）/ L5 融合（分层，见 §4.1 修正 2）
- **L8 召回审计要做**
- L6（证据过滤）/ L7（ContextPack）后续补

**理由（经钢人论证重新表述）**：

L8 是**度量基础设施**，不是度量方法本身 —— 它记录"查了什么、返回什么"，**不能单独回答"生产变好了吗"**。

→ 原表述「无 L8 就无法度量」不准确。修正为：

> **本 program 的验收前提 = L8（基础设施） + 对照评测方法（golden set + 有无经验对照）。二者缺一不可。**

L8 之所以要**早做**，是因为它必须在**第一轮经验复用之前**就位，否则那轮的效果数据无法回收。而对照评测方法可以后定义，但**必须在首个回流包交付前定稿**。

**L6/L7 可后补的理由**：它们作用于**输出**（过滤、打包），不影响"经验有没有被用上"这个核心判据。

### 决策 5：执行顺序 —— 按**原设计的工程机制**，不靠对照实验证明效用

**（2026-09-15 修订：放弃 P0 的对照实验路线）**

原 §15 的阶梯里**没有"证明经验有用"这一步**。它靠的是工程机制：

> 「每次晋级或降级都必须有**回归集、证据 ID、审核结论、版本和回滚点**」
> 「**模型只能提交 diff 提案，不能直接生效**」

即：**经验的生效由「沙箱复现 + 回归集 + 人工审核 + 灰度 + 回滚」决定，不由一次对照实验的平均分决定。**

**owner 2026-09-15 原话**：
> 「质量提升**需要一个外部的标准去评判**，要不然无法判断是否提升了质量。」

→ 在外部标准（真实论文评审）不存在时，**在自造环境里测"效用"本质上是无判据的**。
→ **放弃对照实验，回到原设计的工程机制。**

#### 为什么放弃 P0（实测依据，四次错配）

| 次 | 错配 | 证据 |
|---|---|---|
| 1 | agent 完全不调 LLM | 四条件指标完全相同 |
| 2 | 主指标 `hallucination_ratio` 与"草稿质量"无关 | 实测条件间均为 1.0；其两条输入通道（claims/bindings、结果型数字）在条件间无差 |
| 3 | 自造机械指标受跑间噪声支配 | **`temperature=0` 实测 5/5 输出不同**，长度波动 ±13% |
| 4 | **任务本身没有改进空间** | prompt 已把语料参考草稿整个喂给模型；模型产出是"一段论述"，而"结构完整度"在拿标题存在性评格式 |

叠加 GP-11 的方法学结论：**24 case 严重欠功效**（检出 2–5pp 需 200–400 样本/组）。

**结论：当前条件下测不出效用，且不该为此继续投入。**

#### 修订后的执行顺序

```
P1  写入者重写（适配器模式，0 调用点改动）—— 契约前置
P2  经验成熟度阶梯 X0→X2→X3 + 适用/不适用边界（原 §15 前半）
P3  沙箱复现与回归集（原 §15 的"沙箱复现与回归"+"晋级必须过回归集"）
P4  检索层 L1–L5 + L8（对齐原 §13）
P5  知识体系 §12（revision + statement 绑定 + 受管桥接边）
P6  回流层（双通道）+ 灰度/回滚（原 §15 后半）
P7  用户画像 §14
```

**并行度**：P1 为契约前置；P2 与 P4 可并行；P5 与 P2 文件面不重叠，可并行。

### 决策 6：效用由**沙箱复现 + 回归集**回答，不由对照实验回答（2026-09-15 修订）

原「首个回流包必须先做基线测量」**已撤销**。替代：

| 原设计机制 | 回答什么问题 | 为什么比对照实验好 |
|---|---|---|
| **沙箱复现** | 该经验针对的失败，在受控重放中是否**不再发生** | 判据明确、可复现、**不需要外部质量标准** |
| **回归集** | 该经验的引入是否**破坏了别的场景**（防退化） | 同样是二值/可判定，低方差 |
| **灰度 + 回滚** | 真实环境下的退化能否被**及时发现并撤销** | 把"效用"交给真实反馈，而不是自造指标 |

**这直接对应 GP-10 的实证发现**：Experience-Following 证明**无过滤的经验注入会自降级**，只有「选择性添加 + 删除」才有正收益 → **回归集就是那个"过滤"的工程实现**。

## 4.1 外部调研带来的三条修正（详见 `01-external-research.md`）

调研发现原设计（§12–§15）方向正确，但**有三处需要加固或修正**（调研原文见 ）：

### 修正 1：经验沉淀的定性 —— 「实现设计」→「**实现 + 加固**」

**实证**：LLM 把经验抽象成规则时**系统性剥离适用条件**（`arXiv 2605.12978`：WebShop 0.64→0.20，ARC-AGI 100%→52.6%）；盲目信过期记忆失败率 **74.4%** vs 无记忆 28%（*When Memory Lies*）。

→ 原设计的「适用/不适用边界」**有实证必要性**。但另需补三条原设计未明说的机制：**时效衰减、冲突消解、回滚**。

### 修正 2：融合层**分层**，不统一用 RRF

**判据**：RRF 只在两路信号**正交**时增值（Cormack et al. SIGIR 2009）。小语料（几十~几百条）两路易高度相关。

→ **论文证据大语料** 走 L5 RRF（k=60）；**经验/画像小语料** 走「向量 + 适用条件字段过滤」，**不套 RRF**。

### 修正 3：回流层必须**双通道**

**实证**：推理时 RAG **无法从结构上阻止**模型把上下文当事实（*Grounding is not a prompt*）→ 这正是「经验不能替代论文事实」这条硬约束的**脆弱缝**。

→ **事实通道**（`evidence` 段，带引用，可进论断）与 **经验通道**（`guidance` 段，显式 `experiential` 标注，**禁入事实声明**）**物理分离**。
