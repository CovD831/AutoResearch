# M11-MVP-02 Task-local L3

## State

```text
draft -> implemented -> tested -> handed-off -> integrated
```

## Recall pipeline stage order

- `L0` boundary filtering runs **before any scoring**: `project_id`, `partition` and
  availability are all applied on the raw pool, so a page that is out of scope can
  never be scored, ranked or graph-expanded.
- `L1` lexical recall is Okapi BM25 over field-weighted documents
  (`title` 3.0, `tags` 2.0, `body` 1.0), replacing the previous naive substring count.
- `L2` vector recall is cosine similarity against an injected `EmbeddingProvider`.
- `L2` graph expansion adds same-partition neighbours of the surviving candidates.
- Fusion (RRF) is **not** part of this package; `channel` reports the single arm that
  produced the winning score, never `FUSED`.

## Availability anchoring

- The repository does not define "availability"; the word appears only in the
  M11-MVP-02 clause and its task package.
- Frozen read: a page whose `review_status` is `superseded` is not available;
  `draft`, `published` and a missing status are available.
- The matrix is total and tested in four cells
  (`test_the_availability_matrix_gates_the_shared_l0_boundary`), and it is applied by the
  single gate both arms share (`in_scope`), not by a caller.
- No other availability signal exists on `WikiPage`: `contracts.py` contains no
  `available` / `is_active` / `archived` / `retired` field. The `available` flags in the
  audit lane (`audit_evidence.py:99`, `audit.py:115`) mean "the cited full text could be
  fetched for verification" and are unrelated to page availability.
- `published` keeps its own pre-existing contract requirement (`effective_at`).

## Bound filters

- `require_evidence=True` removes any page without `evidence_ids` from **both** the
  lexical and the vector arm, because both arms draw from the same L0 pool.
- The graph arm applies the same gate to the *resolved neighbour page* before adding
  it, so graph expansion cannot smuggle in an evidence-free page.
- Graph expansion additionally checks `project_id` on both the edge and the resolved
  neighbour page: an edge created in project A may point at a page in project B.
- Cross-partition pages never enter the result set; the result set is single-partition
  per call because `partitions` is the caller's declared scope.

## Audit rules

- Every `retrieve()` writes exactly one `RecallAuditRecord` unless auditing is switched
  off (`recall_audit_enabled=False`); the default is on.
- The persisted record carries the four stage id-sets and the timing map, so the
  subset chain is verifiable straight from storage without re-running the pipeline.
- The invariant `final_hits ⊆ reranked ⊆ deduped ⊆ candidates` is enforced twice: by a
  pydantic model validator (an ill-formed record cannot be constructed) and by a
  persisted-payload assertion in the package tests.
- Audit rows use the existing kind-generic `records` table; no schema change was made
  (and none is possible from this package, since `storage.py` is forbidden here).

## Degradation rules

- The vector arm runs behind exactly one failure boundary: `vector_arm()`
  (`knowledge_retrieval.py:268-300`). Inside it, a provider that raises for **any** reason
  (missing model file, inconsistent vector dimensions, a bug) costs the vector arm and
  nothing else: the lexical arm still answers, and the result says so.
- When no `EmbeddingProvider` is injected the vector arm does **not** run, and the
  result reports the reason instead of inventing a vector score.
- A partially computed vector pass is **discarded as a whole**, never merged: mixing half
  a ranking into a result set would silently produce an incomplete answer. The tests pin
  both halves of this property (the arm returns `{}` *and* the provider really did answer
  two of three calls before failing).
- The boundary catches `Exception`, deliberately **not** `BaseException`:
  `KeyboardInterrupt` / `SystemExit` are process-level signals, not capability failures.
- The degradation reason keeps both the exception type and its message, because "the model
  file is missing" and "the dimensions disagree" need different fixes.
- `retrieval_level` names the arms that actually ran and appends the degradation
  reason, so a fallback can never be read as a vector success.
- The pre-existing vocabulary is preserved for the paths that existed before:
  `lexical`, `lexical+graph`.

## Project scope

- Project scope is a **creation-time input**, not an ambient attribute:
  `KnowledgeService(store, project_id=..., embedding_provider=..., recall_audit_enabled=...)`
  (`knowledge.py:97-119`).
- `retrieve()` is **fail-closed**: without a scope it raises
  `KnowledgeScopeRequiredError` (a `ValueError` subclass) instead of widening the query to
  every project. "We do not know the scope" must never read as "every scope". Moving the
  scope after construction (or clearing it) changes which project is read, or refuses the
  query; it can never fall back to reading all of them.
- The single production entry is
  `AutoResearchApplication.knowledge_scope(project_id, *, embedding_provider=None)`
  (`application.py:256`). `api.py:161` and `cli.py:296` both go through it, and both
  endpoints take the project as a **required** input.
- The app-level shared `self.knowledge` (`application.py:168`) stays an unscoped
  write/index handle (`add_page` / `add_edge` / `list_pages` work from explicit arguments);
  calling `retrieve()` on it raises. That is asserted, not assumed.
- Because the wiring lives outside this package's `allowed_paths`, it is registered as an
  owner-approved deviation (`D-M11-02-07`), not silently absorbed. See the task ledger.

## Fixture policy

- The frozen fixture is offline and synthetic: no network, no model file, no real
  paper, no real experiment output.
- `expected` values are hand-authored from the boundary rules, never regenerated from
  the implementation.
- The fixture is required to discriminate the pre-MVP-02 implementation; a package test
  reconstructs that implementation and asserts the two rankings differ.

## Boundary and rollback

- The package's own paths carry the pipeline; the second round additionally touches the
  production wiring (`application.py`, `api.py`, `cli.py`) and three pre-existing test
  files that construct `KnowledgeService` directly. None of those six paths is in this
  package's `allowed_paths`; the owner approved the scope and every entry is registered in
  the ledger (`D-M11-02-07`) rather than absorbed quietly.
- No shared contract, storage, gate, or project ledger file is changed. Those stay
  forbidden: if a change there becomes necessary, stop and request an owner decision
  instead of widening the diff.
- Rollback for the wiring half is those six paths; the pipeline half (this package's own
  four files) stays valid on its own. M11-MVP-01 behaviour and the frozen contracts stay
  intact either way.
