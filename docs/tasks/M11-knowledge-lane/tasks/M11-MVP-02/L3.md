# M11-MVP-02 Task-local L3

## State

```text
draft -> implemented -> tested -> handed-off -> integrated
```

## Recall pipeline stage order

- `L0` boundary filtering runs **before any scoring**: `project_id`, `partition` and
  availability are all applied on the raw pool, so a page that is out of scope can
  never be scored, ranked or graph-expanded.
- `L1` lexical recall is Okapi BM25 over field-weighted documents
  (`title` 3.0, `tags` 2.0, `body` 1.0), replacing the previous naive substring count.
- `L2` vector recall is cosine similarity against an injected `EmbeddingProvider`.
- `L2` graph expansion adds same-partition neighbours of the surviving candidates.
- Fusion (RRF) is **not** part of this package; `channel` reports the single arm that
  produced the winning score, never `FUSED`.

## Availability anchoring

- The repository does not define "availability"; the word appears only in the
  M11-MVP-02 clause and its task package.
- Anchored read: a page whose `review_status` is `superseded` is not available;
  `draft` and `published` are available. A missing status defaults to available.
- `published` keeps its own pre-existing contract requirement (`effective_at`).

## Bound filters

- `require_evidence=True` removes any page without `evidence_ids` from **both** the
  lexical and the vector arm, because both arms draw from the same L0 pool.
- The graph arm applies the same gate to the *resolved neighbour page* before adding
  it, so graph expansion cannot smuggle in an evidence-free page.
- Graph expansion additionally checks `project_id` on both the edge and the resolved
  neighbour page: an edge created in project A may point at a page in project B.
- Cross-partition pages never enter the result set; the result set is single-partition
  per call because `partitions` is the caller's declared scope.

## Audit rules

- Every `retrieve()` writes exactly one `RecallAuditRecord` unless auditing is switched
  off (`recall_audit_enabled=False`); the default is on.
- The persisted record carries the four stage id-sets and the timing map, so the
  subset chain is verifiable straight from storage without re-running the pipeline.
- The invariant `final_hits ⊆ reranked ⊆ deduped ⊆ candidates` is enforced twice: by a
  pydantic model validator (an ill-formed record cannot be constructed) and by a
  persisted-payload assertion in the package tests.
- Audit rows use the existing kind-generic `records` table; no schema change was made
  (and none is possible from this package, since `storage.py` is forbidden here).

## Degradation rules

- When no `EmbeddingProvider` is injected the vector arm does **not** run, and the
  result reports the reason instead of inventing a vector score.
- `retrieval_level` names the arms that actually ran and appends the degradation
  reason, so a fallback can never be read as a vector success.
- The pre-existing vocabulary is preserved for the paths that existed before:
  `lexical`, `lexical+graph`.

## Project scope

- The L0 `project_id` filter is real and testable, but the service has no project
  scope: `KnowledgeService.__init__` takes only `store` and `relation_registry`, and the
  frozen `retrieve()` signature has no project parameter.
- This package therefore reads an **optional instance attribute** (`project_id`) inside
  `retrieve()`, and exposes `project_id` as an explicit parameter on the new
  `knowledge_retrieval.recall()`.
- Production wiring (constructing or injecting the service per project in
  `application.py` / `api.py` / `cli.py`) is outside this package's allowed paths and
  is owned by the project owner. See the task ledger decision `D-M11-02-01`.

## Fixture policy

- The frozen fixture is offline and synthetic: no network, no model file, no real
  paper, no real experiment output.
- `expected` values are hand-authored from the boundary rules, never regenerated from
  the implementation.
- The fixture is required to discriminate the pre-MVP-02 implementation; a package test
  reconstructs that implementation and asserts the two rankings differ.

## Boundary and rollback

- No shared contract, storage, gate, or project ledger file is changed. Only the
  task-local ledger and this package's own paths are touched.
- If a shared change becomes necessary, stop and request an owner decision rather than
  widening the diff.
- Rollback removes this package's source, test, fixture and record changes; M11-MVP-01
  behaviour and the frozen contracts stay intact.
