## 2. Implemented design

交付物本体在代码里，本节只记决策。

### 2.1 K5 数据模型

`ContextBudget`：`max_tokens`（`gt=0`）/ `max_items_per_kind` / `reserved_ratio`（默认 `0.2`，`0 ≤ r < 1`）/ **`max_tokens_per_kind`**（扩展，见 D-L01-02）。
`usable_tokens = int(max_tokens * (1 - reserved_ratio))` —— 预留输出额度在装配前就被扣掉，而不是装完再后悔。

`ContextSlice`：`slice_id` / `kind` / `refs` / `rendered` / `truncated` / `dropped_refs`，与 K5 字段表逐字对应。
`refs` 与 `dropped_refs` 的元素类型是 `RefId = Annotated[str, StringConstraints(strict=True, min_length=1, max_length=200)]` —— 这一条类型别名就是 K5-4 的机械落点：**非 `str` 或超长一律 `ValidationError`**。

### 2.2 「留分级接口」具体怎么留（R-007 §2 对 L-01 的硬要求）

四处，缺一不可：

1. **`kind` 是开放集合，不是封闭枚举。** `ContextItem.kind` 与 `ContextSlice.kind` 都是 `str`（`min_length=1`），`ContextKind` 枚举只提供 4 个**规范值**（`evidence`/`handoff`/`knowledge`/`guidance`）。这样 M11-04 新增一个 kind **不需要改本模块**。
2. **`ContextAssembler.register_kind(kind, *, tier: int)`** —— 显式加（或重排）一个 kind 到某个 **tier**。`kinds` 属性按 `(tier, label)` 排序返回，装配顺序即 tier 顺序。默认构造注册 4 个规范 kind，tier 0..3。
3. **预算分层：`max_items_per_kind`（条数层）+ `max_tokens_per_kind: dict[str, int] \| None = None`（token 层，扩展，见 D-L01-02b）。** 未在 `max_tokens_per_kind` 里给出 ceiling 的 kind **回落**到全局 `usable_tokens` —— **默认 `None` 时每个 kind 都走这条回落，行为与 K5 原文完全等价**（回落 ≠ 写死，单级调用方照样能用）。
4. **装配主循环按 tier 迭代**，每个 tier 产出**独立 slice**，且每个 tier 有各自独立的 remaining 扣减。因此「分级装配」不需要改结构，只需要 `register_kind` + 分层预算。

**未注册的 kind 显式报错**（`ValueError: unregistered context kind ...`），而不是静默并入其它 tier —— 否则 `register_kind` 就是装饰品，tier 概念也就不成立。

### 2.3 K5 四条不变量

| # | 契约 | 落地 |
|---|---|---|
| **K5-1** | 超限时退回拆分，不得堆砌全文 | 装配器**不拼接全文**：装不下的 item 被丢弃并记入 `dropped_refs`，输出按 kind 拆成多个 slice。测试断言被丢 item 的正文**不出现**在 `rendered` 里 |
| **K5-2** | `truncated=True` ⟹ `dropped_refs` 非空 | `ContextSlice._truncation_must_be_accounted_for`（`model_validator(mode="after")`）。**取严格口径**，见 D-L01-01 |
| **K5-3** | `guidance` 不得进入事实论断 | **本层不做校验、不写断言** —— L2 K5 自己标了「❌ 架构意图，靠输出侧追溯」。本层只做结构半边：guidance 恒定在**末尾 tier**、恒定**独立成 slice**。见 D-L01-04 |
| **K5-4** | `refs` 只存引用 ID | `RefId` 类型别名（strict str + 长度上限）；正文只进 `rendered` |

装配算法（每 tier，确定性）：

```
ceiling = min(budget.kind_token_ceiling(kind), remaining)
for item in tier_items（输入序）:
    if item.tokens is None          -> dropped（未测不等于 0，见 D-L01-03）
    elif 已达 max_items_per_kind    -> dropped
    elif used + item.tokens > ceiling -> dropped
    else                            -> included
```

`truncated = bool(dropped)`；`rendered = "\n".join(included 的 text)`，全空则 `None`。
**`ContextSlice` 里没有"截断某条正文"的路径** —— item 是原子的。这既是 K5-1 的实现方式，也是 D-L01-01 成立的前提。

**`reserved_ratio` 与 `dropped_refs` 的语义边界**（owner 裁决 3 的关注点）：预留额度只改变「装得下 / 装不下」，**不参与丢弃记账**。

1. **预留但未用的额度不产生 `dropped_refs`** —— 在 `usable_tokens` 之内装得下的 item 全部留在 `refs`，`truncated=False`。即：留下的那 20%（`max_tokens - usable_tokens`）**不会被记成「丢弃」**。
2. **因预留而装不下的 item 必须点名记入 `dropped_refs`** —— 它**确实没有进 slice**，隐藏它才是 fail-open。`truncated=True`。

两条分别由 `test_unused_output_reserve_does_not_fabricate_dropped_refs` 与 `test_output_reserve_excludes_an_item_by_naming_it` 断言；判别力由突变 **M10**（忽略预留）证明。

### 2.4 M01-06 交接回放

`HandoffReplayService.by_run(project_id=?, run_id=?)`：
- 只读 `RecordStore.list("handoff", project_id=..., partition="handoffs")` —— 与 `HandoffService.issue` 写的是同一分区，**没有新分区、没有第二套 handoff 类型**；
- 用 `HandoffEnvelope.model_validate` **复用契约类型**还原，按 `(created_at, handoff_id)` 排序；
- 汇总 `artifact_refs`（按 `artifact_id` 去重排序）与 `evidence_ids`（去重排序）—— **全是引用**；
- `gate_decision_ids` 只能按 project 取（`GateDecision` 无 `run_id`），因此记录上**显式声明** `gate_scope="project"`，不让调用方误以为它是 run 作用域。

### 2.5 K6 数据模型与算法

`StateMigration`：`migration_id` / `from_version` / `to_version` / `field_mapping` / `unknown_field_policy`（`Literal["reject","preserve"]`，**无默认值**）/ `defaults`。

- **K6-1**：`unknown_field_policy` 无默认 → 不写就 `ValidationError`；写非法值（如 `"drop"`）也 `ValidationError`。**结构上不可能「默认静默丢弃」**。
- `apply(payload)` 三分类：`field_mapping` 的旧名 → 改名；已在 `known_targets`（映射目标名 ∪ defaults 名）里的 → 视为已迁移，原名保留；其余 → **未知字段**，交给策略。`reject` 抛 `UnknownFieldError`（携带 `.fields`）；`preserve` 原样带入。最后用 `setdefault` 填 `defaults`。
- **K6-2**：全程只依赖 payload 的迭代序 + `defaults` 声明序，无随机、无时间戳、不改入参（`dict(payload)`）；测试断言两次调用结果**逐键相等且键序相同**。
- **K6-3**：`version_key()` 用 `\d+(?:\.\d+)*` 取数字段做元组比较（`v2 < v10`，不是字典序）。`to_version <= from_version` → `ValidationError`。**无数字成分的版本号直接报错，不退化成 0**（见 D-L01-07 与「缺失记成正常值」纪律）。
- 另外三条静默丢值防线（同族缺陷，均在构造期拒绝）：映射多对一（`several source fields`）、`defaults` 被映射遮蔽（`unreachable`）、同一 payload 里新旧名同时出现（`FieldCollisionError`）。
- **既有 `ResearchState` 的版本桥**：`state_version(model)` 把既有 `ResearchState.schema_version`（**`int`**，`contracts.py:642`，实测只出现过 `1`）桥成 K6 的 **`str`** 标签（`1 → "v1"`）。K6 声明 `str`、既有类型是 `int`，两者只在**这一处**对齐，免得每个调用方各造一套标签。无 `int` 版本时**报错**（缺失不当作首个版本）。桥的写入侧不对称，见 D-L01-09。

### 2.6 复用而非重造（开工判据）

`context_assembler.py` / `migration.py` 里出现的既有机制 API 名：`RecordStore.list`、`HandoffEnvelope` / `ArtifactRef` / `AgentId`（`contracts.py`）、`new_id`、`handoffs` 分区的 kind/partition 字面量。**未出现** `knowledge.py` / `storage.py` / `contracts.py` 的写入点，未定义任何第二套 handoff 类型。

## 3. Deliberate non-goals

- **不做** M11-04 的 ContextPack 分级装配本身（L-06 的线）—— 本包只**留接口**（§2.2）。
- **不碰** `knowledge.py` / `storage.py` / `contracts.py`（R-007 §3.2 全局串行点）。本包在自己模块里定义自己的类型。
- **不建**第二套 handoff 类型；不新增分区、不新增表。
- **不为 K5-3 写「通过」断言**（L2 自己把它标为架构意图）。
- **不做** `ContextAssembly` 的跨 kind 去重：同一 `ref_id` 出现在两个 kind 会被两边都收（可见的重复，好过静默丢一个）。M11-04 若要合并需要自己定规则。
- **不做** token 估算本身：`tokens` 由调用方给定，本模块不算字符/模型分词。`tokens=None` 按未测处理而非猜一个数。
- **不做** `MigrationChain` 之外的迁移编排（无持久化迁移表、无自动发现、无版本注册中心）。
- **不做** K6 的**值变换**：`schema_version` 的 bump（`1 → 2`）属于「既有字段改值」，而 K6 只有重命名 + 新字段默认值，**表达不了** → 由调用方在 `apply` 之后自行写。这是契约缺口（D-L01-09），**不在本包内发明 `set_fields` / `constants` 之类的新字段**。
- **不接受** pydantic 模型直接入参：`apply` 只收 `Mapping`，调用方用 `model_dump()`（避免在本模块内引入 `contracts.py` 类型的构造耦合）。

## 7. 边界与遗留

- **K5-1「退回拆分」的解读风险（已闭环）**：本包解读为「**按 `kind` 分层拆成多个 slice + 丢弃溢出项**」，依据是 K5-2 自己要求记录 `dropped_refs`（若语义是「把单条超长 item 切块」，就不会有被丢弃的**引用**）。**owner（同时为 K5 契约作者）已于 2026-09-15 确认：本解读正确，以本实现为准**，无需返工。
- `reserved_ratio` 只扣 token，不管 item 条数 —— 条数上限独立于比率。
- `rendered` 的字节/字符开销不计入 token 预算：预算单位完全由调用方给的 `tokens` 决定。若 M11-04 需要「渲染后仍不超限」，需要在调用方补一步实测或让 `tokens` 含渲染开销。
- `HandoffReplayService.by_run` 全量扫 `handoffs` 分区再按 `run_id` 过滤（`RecordStore.list` 无 run 维度索引）。run 量级大时需要分页，本包未做（与 `A6` 的同类遗留一致）。
- `MigrationChain.migrate` 的 `to_version` 门用 `>` 比较（`to_version <= target` 才应用），因此传入链外版本号（如 `"v99"`）会跑完整链而不是报错 —— 是「取可达目标」语义，未做严格校验。
- **K6 的写侧不对称（D-L01-09）**：`schema_version` 的 bump 必须由调用方在 `apply` 之后写。若 owner 认为「迁移一步完成 v1→v2」是硬要求，需要契约补值变换语义 —— 本包不自行发明。
- `apply` 只收 `Mapping`；传 pydantic 模型会 `TypeError`（`model_dump()` 先行）。这是刻意的边界，不是遗漏。
