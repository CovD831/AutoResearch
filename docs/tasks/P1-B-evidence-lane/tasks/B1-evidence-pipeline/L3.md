# P1-B Task-local L3

> This file is the implementation contract for B1. It does not override R004/R005 or the lane spec.

## L3 state

```text
draft → implemented → tested → handed-off → integrated
```

## Evidence admission data shape

- `EvidenceCandidate` carries `project_id`, `evidence_type`, `grade`, `title`, `claim`, `source_uri`, `source_id`, `locator`, `checksum`, `independent_source`, `metadata`, and `created_at`.
- `EvidenceAdmissionResult` records `candidate_id`, `status`, `evidence_id`, `existing_evidence_id`, and `reasons`.
- Duplicate detection uses the normalized source, locator, checksum, and claim combination.
- Conflict detection blocks a same-source locator with different content.
- Only accepted candidates become formal `EvidenceItem` records.

## SectionPlan / SectionDraft / WritingProfile

- `WritingProfile` is versioned and scoped to the project and section.
- `SectionPlan` stores `objective`, `claims`, `claim_evidence_map`, `evidence_ids`, `artifact_refs`, `experiment_dependencies`, `gaps`, `profile_id`, and `status=planned`.
- `SectionDraft` stores the reviewable body, claims, claim/evidence bindings, unresolved gaps, limitations, notes, and `observed_result_summary=None`.
- `compose_evaluation_section` returns a pipeline result, not a manuscript release artifact.

## BenchmarkPlan

- B1 benchmark output is plan-only.
- Fields: `benchmark_name`, `baseline`, `metrics`, `required_materials`, `risks`, `planned_only=True`, and `observed_result_summary=None`.
- Baselines come from reading-card methods when available; otherwise the fallback comparator is used.
- No observed benchmark outcome may be written into the draft.

## MaterialReadinessResult

- Status values: `ready`, `needs_material`, `blocked`.
- Missing required material blocks drafting.
- Missing optional material is surfaced with action items and keeps the draft reviewable.
- The blocked path is reserved for core gaps such as missing evidence, missing reading cards, or a broken planned-only guard.

## SectionValidationReport

- Verdict values: `verified`, `revise`, `blocked`.
- Blocked readiness short-circuits to a blocked report.
- Observed results, out-of-plan claims, and out-of-plan evidence bindings trigger revise.
- Reported evidence IDs follow the readiness-resolved evidence set.

## Claim / evidence / artifact linkage

- Plan claims come from reading cards and innovations.
- Draft claims must stay inside the plan.
- Claim/evidence bindings must stay aligned with the drafted claims and the planned evidence IDs.
- Reading-card locators are evidence context, not free-form citation placeholders.

## Authorization and input scope

- In scope: `evidence.py`, `writing_service.py`, `pipeline_contracts.py`, `readiness.py`, `benchmark_advisor.py`, `section_validator.py`, and the allowed task tests.
- Out of scope: `application.py`, `storage.py`, `contracts.py`, and `capability.py`.
- No new global agent, store, scheduler, or bus is introduced here.

## State and failure semantics

- Evidence admission failure: duplicate, conflict, or blocked.
- Readiness failure: blocked for core material, needs_material for non-critical gaps.
- Validation failure: revise for fixable contract leaks, blocked for missing core material.
- Unknowns, failures, and limitations remain visible in the output.

## Rollback

- Remove the new pipeline-layer files and restore the prior evidence and writing-service behavior.
- Restore the earlier test layout if the task boundary changes.
- Re-run the repo check after rollback.

## Known limits

- `compose_evaluation_section` stops before drafting when readiness is blocked.
- This slice does not wire a new agent or change the shared runtime contracts.
- Python-based verification is available through the project-local `.venv`; the 2026-09-06 verification used Python 3.12.14, pytest 9.1.1, and ruff 0.16.6.
- Adversarial completeness for missing candidate locators and invalidated-evidence filtering is deferred to B2; B1 review does not certify those edge cases.
