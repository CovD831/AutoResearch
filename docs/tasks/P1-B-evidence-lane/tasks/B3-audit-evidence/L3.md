# B3 Task-local L3: Audit Evidence

## State

```text
draft -> implemented -> tested -> handed-off -> integrated
```

Current state is `tested`. `handed-off` requires the owner to review the
working-tree diff and create the PR; `integrated` requires the PR to be
merged into the upstream mainline.

## Data shape

- `AuditClaim` identifies a claim, its citation IDs, existing evidence IDs,
  and the locator assessment method.
- `CitationRef` is a manuscript citation registry entry and requires a source
  ID, URI, or title so the local resolver can match common citation forms.
- `ResolverSnapshot` contains a version, availability flag, and local
  `ResolverRecord` entries. Records carry publication status and related
  source IDs for corrected/superseded/versioned relations.
- `CorpusSnapshot` contains a version and local documents. A document records
  whether full text is available and maps locators to extracted text.
- `AuditVerdict` carries category, status, method, confidence, source/evidence
  IDs, and reasons.
- `AuditReport` carries the audit identity, snapshot versions, separate
  deterministic/model-assisted verdict lists, reconciliation rows, explicit
  unverified claims, candidates, admissions, and diagnostics.

## Rules

1. Canonicalized input plus corpus version, resolver snapshot version, and
   mode forms the deterministic audit key.
2. Local resolver data determines citation existence and publication status;
   no live response is consulted.
3. Resolver unavailability returns `unknown`. A resolver snapshot that is
   available but lacks the cited source returns existence `fail`.
4. Retracted or withdrawn sources fail. Corrected/superseded/versioned sources
   pass only when related IDs are present and preserved in the verdict.
5. Locator comparison returns `unknown` without local full text. With local
   text, a missing locator or non-matching claim fails.
6. Evidence reconciliation reads through `EvidenceService`; invalid and
   expired IDs fail, while IDs absent from the bounded view are `unknown` and
   cannot support a claim. Invalid evidence remains traceable.
7. No valid evidence binding adds `[未验证]` and an `unknown` verdict.
8. Model-assisted locator assessments stay in their own report list and need
   confidence >= 0.8 to preserve their supplied status.
9. In-runtime candidates are passed to `EvidenceService.admit_candidate()`.
   Standalone mode returns no candidates or admission results.
10. Report persistence is idempotent by audit key, and replay returns the
    stored report without another report event.

## Candidate flow

```text
bounded evidence view -> AuditService -> EvidenceCandidate
                                  -> EvidenceService.admit_candidate()
                                  -> accepted / duplicate / conflict / blocked
```

The audit module never calls `RecordStore.put("evidence", ...)`, constructs a
`GateDecision`, or rewrites a manuscript.

## Fixture policy

Fixtures are synthetic, offline, and explicitly provenance-labelled. They use
`example.invalid` sources and cover current, fabricated, retracted, and
corrected citations. No real-paper retrieval or observed experiment result is
included.

## Known limits

- B3 does not add CLI/MCP entrypoints or runtime application wiring; those are
  separate integration work.
- The resolver and corpus snapshots are caller-supplied local contracts. A
  future resolver adapter must preserve snapshot versioning before it can be
  used by this module.
- Locator matching is deterministic in this slice; the model-assisted path
  accepts an explicitly supplied assessment and retains its confidence.
