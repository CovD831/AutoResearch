# B5 Task-local L3: Real Data Sources & Parsing Layer

## State

```text
draft -> implemented -> tested -> handed-off -> integrated
```

Current state is `tested`. `handed-off` requires owner review and PR creation;
`integrated` requires the PR merged into the upstream mainline.

## Data shape

- `SourceStatus` is a transport-neutral verdict: `found`, `not_found`,
  `retracted`, `corrected`, `unknown`. Live Crossref 404 is deterministic
  `not_found`; retraction/correction come from the ``update-to[]`` relation.
- `TransportOutcome` reports why a live lookup could not be definitive:
  `ok` / `rate_limited` / `timeout` / `unavailable` / `partial`.
- `DoiVerdict` carries the DOI, status, metadata, `related_dois`, and the
  transport outcome. Live Crossref is primary; an offline `SourceSnapshot` is
  the fallback; then `unknown` — in that order, never a fabricated verdict.
- `CrossrefClient` uses ``httpx`` with a polite-pool ``User-Agent`` and an
  injectable transport (tests use ``httpx.MockTransport``).
- `GoldSetItem`/`GoldCitation`/`EvalMetrics` describe the evaluation corpus.
  Metrics follow ScholarQABench: ``hallucination_ratio`` = unresolved cited
  papers / total cited; ``citation_recall``/``citation_precision`` need the NLI
  "attributable" judgment and report ``None`` plus a note when it is absent.
- `ParseResult`/`ParseEgress` keep docling-first pymupdf4llm-fallback parsing
  and candidate-only egress.

## Rules

1. Live Crossref first, offline snapshot fallback, then `unknown`. A live 404
   is deterministic `not_found`; rate-limit, timeout, and unavailable downgrade
   to the snapshot then `unknown`.
2. Retraction and correction facts project to B3 resolver material
   (`resolver_record`) and never write evidence directly or judge claim truth.
3. Parsing is docling-first; pymupdf4llm (AGPL) fallback records a diagnostic
   when used; neither available yields `unknown`.
4. Every parsed payload leaves as an `EvidenceCandidate` and is admitted only
   through `EvidenceService.admit_candidate()`.
5. Empty search results follow D-F8-01 (`completed_empty`).
6. Metrics use the ScholarQABench definitions; NLI attribution is a separate
   model-assisted layer that A5 wires, not computed here (it accepts the
   supplied judgments only).

## Fixture policy

The offline snapshot uses **real DOIs** whose status was verified against the
live Crossref API during development (Nature OpenScholar paper and the Lancet
MMR retraction case). The ``crossref_responses.json`` fixture reproduces those
observed Crossref ``message`` payloads for offline replay. No fabricated real
DOI is invented beyond these verified records.

## Known limits

- ``citation_recall``/``citation_precision`` are computed only when an external
  NLI "attributable" judgment is supplied; this layer does not run the judge.
- docling weights are not downloaded; offline pre-provisioning is shared with
  A7 and lands later.
- Live Crossref is polite-pool only; a production rate-limit strategy is
  recorded in the transport-outcome matrix but no paid tier is used.
