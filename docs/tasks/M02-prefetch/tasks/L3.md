### 2.3 ⚠️ K8 没有幂等键：契约空白 + 本包处置（**不自行补边界**）

**空白（L-04 实测指出）**：K8 冻结字段表里没有幂等键，只有 `propagation_id`。而 `propagation_id` 由 `plan()` **每次新铸** → **重试路径每轮换键**，于是「同一 evidence 重复失效要不要折叠」**契约没规定**。

**本包的处置（只给机制，不替 owner 定策略）**：

- `plan()` / `propagate()` 新增**可选**参数 `propagation_id: str | None = None`。不传 → 维持现状（每次新身份，两次调用 = 两条事实）；传了 → 调用方**自己**决定「什么算同一次失效」，`record()` 的幂等守卫随之生效。
- **不在本包内做确定性派生**：把 `propagation_id` 改成按 `(source_evidence_id, reason)` 派生会**改变 K8 的 id 语义**（两条真的独立传播会撞成一条），那属于**契约修订**，不在 L-02 权限内。
- **`record()` 的冲突判据按「事实」而非「时间戳」**：新增 `VOLATILE_FIELDS = {"created_at"}`，比较时排除。理由见 §2.4 —— 这正是本包自己写的新测试抓出来的缺陷。

### 2.4 一个被自己的测试抓住的缺陷（登记）

`record()` 的冲突判据原先直接比 `model_dump(mode="json")` 全量。于是**「稳定 id + 重试」这条路根本不成立**：`plan()` 每次构造都会刷新 `created_at`，两次 payload 必然不等 → 抛 `InvalidationContractError`。

**性质**：不是 fail-open，是**fail-closed 方向挡住了合法重试**（比静默放过正确，但功能等于没做）。抓住它的是我**新写的** `test_a_caller_supplied_identity_folds_a_retry_onto_one_record` —— 第一次跑就红。

**修法**：比较**排除 `created_at`** 的事实负荷；折叠时返回**已落库的那条**（原始时间戳、原始事实），而不是重试的临时对象。

### 2.5 🔴 K7-1 的代码结构层补偿（本包最容易写错的地方）

**事实认定**：K7-1「L2+ 动作前必须写一条」是**时序型约束**。validator 只能校验字段内容，**校验不了"某动作发生前已写记录"**。L2 §K7 已由第 1 关 B1 修正为此表述，本包与之对齐。

**补偿（已实现）**：L2+ 动作走**唯一入口** `EvidencePrefetchService.execute_l2_action()`，结构上三件事同时成立：

1. **入口唯一**：`execute_l2_action()` 对 `action_level < 2` 直接 `ValueError` 拒绝（L0/L1 走 `write_prefetch()`）。
2. **先写后执行 + 动作签名强制携带记录**：`action` 的签名是 `Callable[[PrefetchRecord], T]` —— 动作体**只能**通过入口刚写好的记录被调用。动作想跑，就得先有记录；记录不存在，动作连调用形状都没有。
3. **fail-closed 短路**：`decision == blocked` 时入口**不调用** `action`，只返回 `executed=False` 的 `PrefetchOutcome`。

**这三条能证明什么、不能证明什么（必须说清）**：

- **能证明**：凡经由本模块入口驱动的 L2+ 动作，其 `PrefetchRecord` 必然先于动作落库；被拦的动作不会执行。
- **不能证明**（**架构意图部分**）：本模块**无法**阻止别的模块绕过 `execute_l2_action()` 直接做 L2+ 动作。这是时序约束不可机械校验的根因，**本包不假装它被校验了**。
- **另一处必须说清的口径**：`write_prefetch()` 是**层级无关**的（L0–L4 都收）。所以「唯一入口」的准确含义是 —— **`execute_l2_action()` 是唯一"驱动动作"的入口**，**不是**"唯一写记录的入口"。一个模块完全可以自己调 `write_prefetch(action_level=3, ...)` 拿到记录、再自己执行动作（这正是上一条不可证明的部分在代码里的形状）。**不要把"入口唯一"读成"L2+ 记录只可能由该入口产生"。**
- **K7-1 的表述按两层，别压成一句**（falsify-r007 纠正后改定）：
  - **全局层**：K7-1「任何模块的 L2+ 动作前必须写一条」是**时序型约束**，validator 校验不了，**测试也校验不了**（它得约束别的模块的代码）。**这一层没有任何「通过」断言，且不可能有。**
  - **本入口层**：`execute_l2_action()` 可达范围内「**记录先于动作体落库**」**有断言、可被证伪、范围受限** —— `test_l2_entry_passes_the_written_record_into_the_action` 在「把落库推迟到 action 之后」的突变下以**判据型**失败（`AssertionError: assert None is not None`）。它是这条补偿的**唯一顺序判据**。
  - **我此前写「没有为 K7-1 写任何『通过』断言」是过于绝对的表述**，已按此两层改定 —— 把一条有判别力的顺序断言自谦成「非不变量断言」，与夸大一样是失真。
- **单写入点守卫的边界已实测，不是声明**（falsify-r007 报 R3，本包复现并修）：
  - AST 守卫（`test_write_path_has_exactly_one_call_site`）**只匹配一种字面语法形状** —— `getattr(self.store, "put")(...)`、模块级别名 `_PUT = RecordStore.put`、绑定别名 `_p = self.store.put`、`transaction() + _write_record` **全部绕过它**，且**全量套件保持全绿**（已复现）。**已降级为辅助**。
  - **主守卫换成运行期判据** `test_prefetch_is_written_exactly_once_per_entry_call`（A+C：`store.put` 打桩计数 + **不加 partition 过滤**的落库条数）。实测在四种绕过形态上**全部开火**，干净代码静默。**A 与 C 必须合用**：实测「带 partition 过滤的计数」（B）会漏掉省略 `partition=` 的写入 —— 我最初打算交付的正是 B。
  - **三条已声明的边界**（写进测试 docstring，实测得出）：未走到的分支；别的 kind + 别的 handle；**在 `write_prefetch`/`execute_l2_action` 作用域之外的写入**（falsify-r007 在 `context_assembler.py` 的 `HandoffReplayService.by_run` 里插入 `PREFETCH_RECORD_KIND` 写入，**全量零检出，本守卫同样漏**）。守这条需要**存储层不变量**，不是本模块的测试能覆盖的。

### 2.6 ⚠️ 运行标识：引用 K1，未自造

**开工时**（本 worktree 建起时）：`run_manifest.py`（K1，L-05 独占）**实测不存在** → 当时按约定先做不依赖运行标识的部分。

**实现收尾时复测**：K1 已由 L-05 落地（`../r007-l05-execution/src/autoresearch/run_manifest.py`，8768 bytes），其 docstring 第 10 行明文：`L-02 PrefetchRecord -- run_id must reference RunManifest.run_id`。**但该文件是 L-05 分支上的 untracked 文件**（`git status` = `?? src/autoresearch/run_manifest.py`，HEAD 仍 == `main@8dd8780`）→ **不在 main，本分支 import 不到**。

**因此本包采用 duck-typing 接线，而不是 `import`**：

```python
def write_prefetch_for_run(self, manifest, *, ...) -> PrefetchRecord:
    return self.write_prefetch(..., run_id=manifest.run_id)
```

**为什么不上 `import`**：K1 未入 main 时 import 会让本模块**在自己的分支上不可导入**（全量测试直接红）—— 这正是 R-006 栽过的「stacked 分支」故障。K1 的契约面就是 `.run_id` 一个属性（K1 自己的 docstring 已声明），duck-typing 零成本且保持本 lane **可独立合并**。`test_run_id_is_taken_from_the_manifest_not_generated` 用 stub manifest 钉住该接线。

**本包仍不生成运行标识**：无 `new_id("run")`、不 import 任何 run 抽象（AST 断言守护）。

- `PrefetchRecord` 设 `run_id: str | None = None`，**值域完全由 K1 决定**。
- L-05 合入 main 后，只需把 `manifest`（真实 `RunManifest`）传给 `write_prefetch_for_run()`，**不需要改契约、不需要改本模块结构**。

## 5. 判别力证据

### 5.1 局限声明（先说结论）

`evidence_prefetch.py` / `invalidation.py` 是**全新文件**（greenfield）。因此新增测试在**修复前基线**（`main@8dd8780`）上失败的类型是 **`ModuleNotFoundError`（符号缺失型）**——按本项目纪律，**符号缺失型失败不计入判别力证据**。

**所以本包的判别力用「变异测试（mutation）」建立**：在**已实现**的代码上逐个摘掉不变量守卫，确认对应测试以**判据型**失败（断言失败 / `ValidationError` / `BrokenPropagationError`），而不是 `ImportError` / `AttributeError`。
