## 2. Implemented design

交付物本体在代码里，本节只记**决策**与**边界**。

### 2.1 `acl.py`（K11）

| 落地 | 类型 |
|---|---|
| `ResourceKind` | `StrEnum`：`project` / `partition` / `artifact` |
| `ResourceAction` | `StrEnum`：`read` / `write` / `export` / `delete` |
| `ELEVATED_ACTIONS` | `frozenset{export, delete}` —— K11-3 的判据本体 |
| `AccessPolicy` | pydantic 模型；`actions: list[ResourceAction]`（**类型收窄**：L2 写 `list[str]`，StrEnum 成员即字符串，入参 `"read"` 仍被强制转换） |
| `AccessDecision` | `allowed` / `reason` / `policy` / `elevated` |
| `AccessDenied(PermissionError)` | 携带 `decision`，可被上层捕获后计数 |
| `AccessPolicyStore` | `grant(policy, *, justification=None)` / `revoke(...)` / `check(...)` / `require(...)` / `readable_resources(...)` / `.denials` |

**K11-1 默认拒绝的落法**：`check()` 以 `allowed=False, reason="no_policy"` 起步，只有命中一条 `granted=True` 且 `action ∈ actions` 的策略才翻转。
`granted=False` 的策略（显式否认 / 未显式授权）与「无策略」用**不同 reason** 区分（`policy_not_granted` vs `no_policy`）—— 两者都拒绝，但可观测性不同。

**K11-2 越权可观测的落法**（两条互补通道）：

1. `require()`：拒绝即 `raise AccessDenied`，**并把拒绝写入 `denials` 日志**。
2. `readable_resources()`：**主体对该 kind 无任何策略时 `raise AccessDenied`，不返回 `[]`**。
   理由：`[]` 与「你有权限但确实没有资源」不可分辨 —— 这正是 K11-2 点名的缺陷。
   有策略但未覆盖某资源时返回过滤后的子集（可能为空），这是合法语义。

**K11-3 更高门槛的落法**：`grant()` 对覆盖 `export`/`delete` 且 `granted=True` 的策略强制要求非空 `justification`，否则 `MissingJustification`；
授权时**再次校验** justification 仍在位（防止先 grant 后 justification 被抹掉）。
justification **按动作存**（`{action: justification}`，非每行一条）：为 `export` 写的理由**不得**顺带覆盖事后被加宽进来的 `delete`。
该性质有独立用例 `test_a_justification_covers_only_the_action_it_was_written_for`，以及对应变异点 **M10**（逐动作查找退化为行级查找 → 判据型红）。

### 2.2 `pii.py`（K12）

| 落地 | 类型 |
|---|---|
| `SensitivityClass` | `StrEnum`：`public` / `internal` / `sensitive` |
| `DEFERRED_INVARIANTS` | `MappingProxyType[str, str]`：**机器可读的生效阶段登记表** |
| `PiiSpan` | `kind` / `start` / `end` —— **只存位置，不存命中原文**（存原文即本模块要防的泄漏） |
| `SensitivityLabel` | 资源 → 敏感级别的绑定（`label_id` / `resource_kind` / `resource_id` / `sensitivity` / `assigned_by` / `created_at`） |
| `PiiScanResult` | `resource_id` / `scanner` / **`value: int \| None`** / `spans`；`value is None` ⟺ 未测 |
| `scan_for_pii(text, *, resource_id, scanner=None, scanner_name=None)` | `scanner=None` → **`value=None`（未测）**，返回空 `spans`，**绝不用 0 顶替** |
| `default_scanner` | 内置正则扫描（email / phone）—— 离线可跑，不引依赖 |
| `TraceAction` | `StrEnum`：`export` / `delete` |
| `SensitivityTrace` | `trace_id` / `action` / `resource_id` / `sensitivity` / `subject` / `reason` / `created_at` |
| `SensitivityLedger` | `label(...)` / `sensitivity_of(...)` / `record(...)` / `.traces` |

**为何 `value` 是 `int | None` 而不是 `float`**：K13 的 `TelemetryPoint.value` 是 `float`（承载 `latency_ms`/`cost_usd`）；
PII 侧的 `value` 是**计数**，整数才诚实。**两者共享的是判据**（`None` = 未测），不是类型 —— L3 登记在案。

**K12① 空约束的正确落地（**核心**）**：
- `SensitivityClass.SENSITIVE` 的语义（禁 embeddding / 送外部模型）**只登记在 `DEFERRED_INVARIANTS["K12.SENSITIVE_FORBIDS_EMBEDDING"]` 与 docstring**，标注 `【向量落地后生效】`。
- **没有**任何断言声称该约束成立。测试里唯一相关的一条守卫的是「标注是否还在」这个**文档事实**（`test_sensitive_embedding_ban_is_annotated_not_asserted`），
  它**不是**对不变量的「通过」断言 —— 断的是一句可读的字符串是否存在，删掉标注它就红。这条守卫在 L3 §4 显式登记为**非证据型**。
- 例外说明：R-007 §5 要求「禁止为其写通过断言」，本包照办；`DEFERRED_INVARIANTS` 是**登记**，不是断言。

**K12② 导出/删除可追溯的落法**：`SensitivityLedger.record()` 要求 (a) 资源**已被分类**（未分类 → `UnclassifiedExport`，fail-closed）、
(b) `reason` **非空**（否则 `UntraceableExport`），随后落一条 `SensitivityTrace`。删除与导出走同一通道，二者都可追溯。

> ⚠️ **这不闭合负例 N-4**。N-4（尝试写入 prompt/全文/secrets → 被拒或被脱敏，不得落盘原文）是 **K13-3** 的性质，
> 随 `telemetry.py` 一并挂起（§5 S-4）。本包只贡献两条**相邻但不同**的性质：
> `PiiSpan` 只存偏移不存命中原文（`test_spans_carry_offsets_not_the_secret_text`）、出网必须留因。
> **不得把这两条当作 N-4 的证据。**

> **与 ACL 的分工**：ACL 回答「**允不允许**」，`SensitivityLedger` 回答「**留没留痕**」。两者不互相调用（各自独立可测），组合由调用方负责 —— 见 §5 未闭合项。

### 2.3 `licensing.py`（M14-05，**策略与门禁层**）

| 落地 | 类型 |
|---|---|
| `LicenseTerm` | `StrEnum`：`open_access` / `licensed` / `paywalled` / `unknown` |
| `LicenseAction` | `StrEnum`：`read` / `export` |
| `Entitlement` | `subject` / `resource_id` / `actions` / `valid_until(nullable)` / **`reference`（权利凭证引用，非内容）** |
| `LicenseDecision` | `allowed` / `reason` / `term` / `entitlement` |
| `LicenseViolation(PermissionError)` | 携带 `decision` |
| `LicenseGate` | `register_entitlement(...)` / `check(...)` / `require(...)` / `.violations` |

**判定表（fail-closed）**：

| `term` | `read` | `export` | 说明 |
|---|---|---|---|
| `open_access` | ✅ | ✅ | `reason="open_access"` |
| `licensed` | 需权利 | 需权利 | 无权利 → 拒（`entitlement_required`）；过期 → 拒（`entitlement_expired`） |
| `paywalled` | 需权利 | 需权利 | 无权利 → 拒（**`paywall`**，N-5）；过期 → 拒 |
| `unknown` | ❌ | ❌ | **恒拒（`license_unknown`）—— 未判定不得当作 open**（本项目缺陷族） |

**与 L-04 的分工（不越界）**：本模块**不判定**许可事实（哪篇是 OA / 是否撤稿 = L-04 的 `external_sources.py`）；
`LicenseTerm` 是**入参**，由上游/来源声明给出。本模块只做「谁能 read/export」的**策略与门禁**。
「绕过付费墙」在本模块里**没有实现路径** —— `LicenseGate` 不提供任何 bypass/force 参数，N-5 断言的正是「不存在这条路」。

### 2.4 `telemetry.py`（K13 / M15-02 / M15-04）

| 落地 | 类型 |
|---|---|
| `Metric` | `StrEnum`：`blocked` / `denied` / `retry` / `latency_ms` / `cost_usd` |
| `DIMENSION_KEYS` | `frozenset{project, run, node, agent, gate}` —— **K13-3 白名单的判据本体** |
| `TelemetryPoint` | `metric` / `dimensions` / **`value: float \| None`** / `threshold` / `redacted` / `point_id` / `created_at` |
| `TelemetrySink` | `record()` / `record_all()` / `.points` / `.breaches` / **`.unmeasured`** |
| `ThresholdBreach` | 一次越阈记录 |
| `cost_usd_point()` | **K13-2 成本口径**（复用 O12 `price_source` + `attempts`） |
| `run_id_of()` / `dimensions_for()` | K1 挂接（结构依赖，不 import） |
| `redact_value()` / `redact_health_report()` / `doctor_diagnostics()` | **M15-02 脱敏纯函数**（可接线） |
| `TelemetryError` / `SensitiveDimension` / `TelemetryInterrupt` | 三类失败 |

**K13-1 的落法（本项目血泪条款）**：`value` 的**默认值就是 `None`**，全模块没有任何一处把 `None` 折成 0。
并且把同一条纪律**再推一步**：`TelemetryPoint.breaches_threshold` 是 **`bool | None`** ——

| 情形 | 返回值 | 含义 |
|---|---|---|
| 未配阈值（`threshold is None`） | `False` | 没有上限，谈不上越阈 |
| 配了阈值但 `value is None` | **`None`** | **不知道** —— 不是「合格」 |
| 配了阈值且 `value > threshold` | `True` | 越阈 |

`None` 是 falsy，所以 `if point.breaches_threshold:` 会把**未测读成健康**（正是 K13-1 要挡的缺陷）。
因此 `TelemetrySink.record()` **显式分支**（`is None` / `is True`），并把未测点放进 **`.unmeasured`** 而不是丢掉 —— 未测是可观测的缺口，不是通过。

**K13-2 的落法**：`cost_usd_point(total, price_source, attempts)` —— `price_source is None` ⟺ 无价目 ⟺ `value=None`
（口径同 `provider_lane.py:388-424` 的「unpriced lane 必须两边都是 None」）。`attempts` 按 `total × attempts` 折成**上限**，
与 `provider_lane.receipt_usage_fields`（`:1630`）同源；因为 K13-3 的维度白名单固定五个键，`attempts` 不作为维度，只体现在值与函数契约里（已登记为已知边界）。

**K13-3 的落法（白名单 + 扫描 + 无自由文本字段）**：
1. **字段白名单**：`dimensions` 只允许五个契约键；出现别的键**直接拒绝**（不是静默丢弃）——「prompt / 全文 / token / secrets」没有键可以搭车。
2. **内容扫描**：值必须是非空、≤200 字符、**不含换行**（全文/prompt 必然超长或含换行），且不得命中
   secret/token 模式（`sk-…`、`ghp_…`、`xox…`、私钥头、`Bearer <token>`、`api_key=…`）或 PII 模式（邮件/带分隔的电话；复用 `pii.default_scanner`）。
3. **`redacted=False` 一律拒绝**：本模块只产出已脱敏点，没有「不脱敏模式」。
4. **M15-02 脱敏纯函数**：`redact_value()` 两条独立规则（**键名规则** + **内容规则**）—— 任一单独都不够；
   超长值截断并标注原长。`redact_health_report()` 保持 `doctor()` 的字典形状，`doctor_diagnostics()` 只为**不健康**信号出诊断行。

**K13-4 的落法**：越阈 → 记 `ThresholdBreach` + 抛 `TelemetryInterrupt`（点本身**仍被记录** —— interrupt 不得抹掉证据）；
`record_all()` 可在不中断的前提下收集多点越阈。**实现为异常，不是 langgraph interrupt** —— 见 §4 D-L09-08。
