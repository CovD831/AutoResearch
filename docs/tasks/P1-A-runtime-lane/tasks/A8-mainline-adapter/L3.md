## 3. 关键约束（实测得出，不是推测）

### 3.1 `search_service.py` 不能删

全仓引用面：

```

```

A1/A2 的 recovery contract 测试**直接构造 `PaperSearchService`**。删除会破坏 `04ce9a9` 的 509 passed 基线。
→ **本包保留老服务不动**，只换主链路装配目标。

### 3.2 不能依赖 `CapabilityAdapterResult.value` 通道

`capability_registry.py:645-648`：

```python
if registration.trust_tier == CapabilityTrustTier.CANDIDATE_ONLY:
    if value is not None and not candidates:
        diagnostics.append("candidate_only adapter returned no EvidenceCandidate")
        status = CapabilityReceiptStatus.FAILED
        value = None
    else:
        value = None          # ← CANDIDATE_ONLY 的 value 被强制清空
```

检索 adapter 注册为 `CANDIDATE_ONLY`（A5 `D-A5-01`），**所以 `value` 一定会被 registry 丢弃**。这是有意设计。
→ 主链路不能靠 registry 的 value 通道拿结构化结果。

### 3.3 `_candidate()` 丢了 abstract 正文

`search_adapters.py:385-405` 的 `metadata` 只有 `abstract_present`（布尔），没有 abstract 正文。
而 `reader_service.py:69-71`：

```python
source_text = full_text or paper.abstract
if not source_text:
    source_text = paper.title          # ← 降级到只读标题
```

→ 若主链路只经候选中转，**44 篇论文会全部退化成"只有标题"**，阅读卡质量崩溃。
这与我们记录的缺陷族「退化路径上把未知记成正常值」同型——**必须在设计阶段挡掉，不能等它在真实运行里以"能跑通"的面目出现**。

## 4. 设计

### 4.1 新增公开原语 `retrieve()`

在 `_CandidateOnlyAdapter` 上把 `_fetch()` 提升为公开的：

```python
def retrieve(self, request: SearchAdapterRequest) -> list[RetrievedPaper]:
    """Provider fetch with limit accounting. Returns raw hits (abstract included).

    Separate from invoke(): invoke() is the candidate-only contract boundary
    (never a structured value), while retrieve() is the raw provider primitive
    a mainline assembler may call when it needs the material itself.
    """
```

- `invoke()` 改为调用 `retrieve()`（行为不变，候选语义不变）
- **限流计数下沉到 `retrieve()`**（`rate_limit_events` / `last_retry_after_seconds`），
  这样 `invoke()` 与主链路**共享同一个 limit-monitor 面**，不新增第二套。

### 4.2 新增 `AdapterBackedPaperSearchService`

新文件 `src/autoresearch/adapter_search_service.py`，**满足 `PaperSearchServicePort`**：

```python
class AdapterBackedPaperSearchService:
    def __init__(self, store, evidence, knowledge, *, settings, adapters=None): ...
    def search(self, project_id, queries, *, seed_papers=None, per_connector_limit=5) -> SearchOutcome: ...
```

行为：
1. 用 `build_search_adapters(settings=settings)` 构造 A5 adapter 集合
2. 对每个 query × 每个 adapter 调 `retrieve()`
3. `RetrievedPaper` → `PaperRecord`（字段一一对应，`source` 取 adapter 的 `source`）
4. **复刻老路径的落库副作用**：`store.put("paper")` + `EvidenceItem(E1)` + `WikiPage`
   —— 下游 `PaperReaderAgent` 按 `paper_id` 从 store 取记录，这条链不能断
5. 去重键沿用老服务的 `_dedupe_key` 语义（doi 优先，否则归一化标题）
6. 异常按 `RetrievalRateLimited` / `RetrievalUnavailable` / `RetrievalError` 分流成 diagnostics，
   **失败不得静默退化成"零命中成功"**（D-F8-01 只适用于"合法查询真的零命中"）

### 4.3 装配改动（`application.py`）

```python
self.search = AdapterBackedPaperSearchService(...)   # 只换这一处
self.search_capability = PaperSearchCapabilityAdapter(self.search, self.store)   # 不动
self.search_port = InvocationBoundedSearchPort(self.search_capability)           # 不动
```

**`PaperSearchCapabilityAdapter` / `InvocationBoundedSearchPort`（A4 幂等/replay/recovery 边界）原样保留**
——它们只依赖 `PaperSearchServicePort` 这个 Protocol，换实现不需要改它们。
