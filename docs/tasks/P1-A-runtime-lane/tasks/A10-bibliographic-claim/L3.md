## 1. F4：畸形/缺失命中被铸成受信任的 E1 证据

### 缺陷现场（实测复现）

| 场景 | 修复前行为 |
|---|---|
| `RetrievedPaper(title="Real paper", abstract="")` | 落库 claim = `"This scholarly record and its supplied abstract exist in the cited source."`，而**同一次调用写出的 `WikiPage.body` = `"No abstract was supplied."`** —— 一个记录的两句事实互相矛盾 |
| `RetrievedPaper(title="Untitled")`（doi/url/source_record_id 全 `None`） | 仍被铸成 **E1** 证据，`independent_source` 退化为 `"s:None"` |

**危害**：E1 权重 15（`gates.py`），虚假 E1 会喂给门禁决策。属「把不存在的输入记成正常值」缺陷族。

### 我先前对"被 parity 锁定"的判断有误 —— 已修正

上一轮我判定"claim 文案被 A1 parity 契约锁定，改动需 owner 裁决"。**复核后这个判断过重**：

- `tests/test_recovery_contract.py:193` 的 parity 测试比对的是 **`PaperSearchService` vs `PaperSearchCapabilityAdapter(PaperSearchService)`** —— **两侧都是老服务**，比对的是各自数据库的投影，不是 fixture 快照；
- **全仓没有任何测试断言 claim 字符串**（机械 grep 确认：只有两处源码 + 一份 A1 时期的历史 JSON）；
- `docs/rearchitecture/worktrees/A-runtime-recovery/parity-report.json` 是 **A1 验收的历史证据**（`schema: p1-a-parity-report/v1`），不是活契约。**改它等于伪造当时的验收记录，故不动它。**

→ 结论：**两处实现同步修改即可**，parity 自动成立。

### 修复

1. **提取共享写入函数** `persist_bibliographic_record`（`search_service.py`）。
   **理由（skill 3.5）**：两份 `_persist` 是复制粘贴，而 A1 parity 要求 `durable_facts_equal` —— **这条不变量此前靠"两个编辑者记得同步"维持，这正是矛盾 claim 能在两处同时存活的原因**。提取后 parity 成为**结构性**的。
2. **`evidence_claim_for(paper)`**：有 abstract 才声称 abstract 存在；无 abstract 只声称书目记录存在。
3. **`independent_source_for(paper)`**：无 doi/url/source_record_id 时返回 `None`（而非 `"s:None"`）。
4. **拒绝不可归属的检索命中**：写诊断并跳过，**不铸 E1**。选择"跳过"而非"抛错"，因为一个坏命中不应丢弃旁边的好命中。
5. **locator 同步**：无 abstract 时 `"bibliographic record"`（不再声称 `/abstract`）。

### 修复过程中发现的**过度收紧**（已修正，值得记录）

第一版把"无可归属标识"判定为无条件拒绝，**结果连用户的 seed 也一起拒了** —— `test_seed_papers_still_flow_with_the_network_disabled` 当场变红。

**根因**：用户通过 `--seed-file` 提供 JSON，而 `PaperRecord.doi` / `.url` 都是**可选字段**（`contracts.py:228-229`），所以**合法 seed 完全可能没有标识**。它的归属就是用户本人。

**修正**：加 `require_provenance` 概念 —— **只有检索命中要求可归属**；用户 seed 用 `independent_source = f"user_supplied:{paper.source}"`。

**并且**：可归属判定放在 `search()` 调用点而非 `_persist` 内，因为 **A2 的故障矩阵 override 的是 `_persist(self, paper)`**（`tests/a2_runtime_fixtures.py:167`）。给 `_persist` 加 kwarg 会让那个 crash 注入**静默失效**（实测：注入不发生 → 子进程跑完 → `recover_pending` 报 "already finalized"，两条 A2 测试变红）。这是 skill 记过的「注入点会随实现迁移」的又一次实证。

## 2. N1：部分失败被静默

### 缺陷现场

主源 `semantic_scholar` fail-closed（无凭据）、`arxiv` 被限流，但 `openalex` 成功返回论文 → **`receipt.status = COMPLETED`**，用户**不知道主源从未工作**。

**根因**：`capability.py:74-76` 的 `_status()` —— **只要有 papers 就是 `COMPLETED`**。这是 A1 的既有语义，**不能改**（改它会破坏既有测试，且属设计决策）。

### 修复：把事实与状态分开

**不改 status 语义**，而是让"有源失败"这一**事实**穿过边界：

1. `InvocationReceipt` 新增 `provider_failure: bool = False`（`invocation_contracts.py`）。**向后兼容** —— 实测旧记录（无该字段）反序列化正常，取默认 `False`，idempotency replay 不受影响。
2. `PaperSearchCapabilityAdapter._outcome_parts` 额外返回该事实（从 `SearchOutcome.provider_failure` 取），`_build_result` 写入 receipt；`recover_pending` 与异常路径置 `True`。
3. `InvocationBoundedSearchPort` 读 `receipt.provider_failure`（不再仅凭 status 推导）。

### 实测效果

```
papers: 1                        ← 次源成功
receipt.status: completed        ← 既有语义未变
receipt.provider_failure: True   ← 事实被保住 ✓
```

## 3. 不变式

- 证据的 claim 必须描述**实际存在的材料**；同一记录的两处陈述不得矛盾。
- 不可归属的**检索命中**不得铸 E1；用户提供的 seed 不受此限。
- 部分失败是**事实**，必须可观测；不得因"有结果"而隐藏。
- 两条检索路径的持久化必须**同源**（A1 parity 的结构性保证）。
- 不改 `_status()` 的既有语义（A1 决策）。
- 不改 `parity-report.json`（历史验收证据）。
