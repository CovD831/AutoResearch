# S2-A Audit Runtime L3

## Task source

The A3 task requires “提供 Audit CLI/stdio runtime 的调用边界和 resolver adapter，
不直接写 EvidenceItem” (`TASK-SPECS.md:39`) and the R-004 contract requires
“只读 bounded evidence view” plus `AuditReport`/verdict/candidate output
(`R004-trust-program/04-l2-contracts.md:48-56`).

## Implemented design

1. `AuditInvocationRequest` freezes manuscript hash, corpus version, resolver
   snapshot version, claims, citations, enabled categories, and runtime mode.
2. `ResolverSnapshot` is a checksum-verified, versioned input. `ResolverSnapshotRepository`
   stores the original snapshot as a `resolver_snapshot` record in the existing SQLite
   `RecordStore`; the same version cannot be silently replaced with different content.
   `SnapshotResolverAdapter` can load that record after a new process starts. An unavailable
   adapter returns an explicit unavailable response; `AuditRuntime` maps it to `unknown`.
3. `BoundedEvidenceView` exposes only evidence id/source/locator/validity/full-text
   availability. The Audit module never receives an `EvidenceItem` writer.
4. `AuditRuntime` produces deterministic `AuditVerdict` records for existence,
   locator, retraction, correction, and claim binding. It creates an
   `AuditReport` artifact through `AuditPersistencePort`; the current
   `RecordStoreAuditPersistence` implementation writes to the canonical SQLite store.
   Candidates are emitted only in `in-runtime` mode.
5. Idempotency uses audit content plus corpus/snapshot versions. A matching report
   is replayed without a second report artifact or resolver decision.
6. CLI accepts a request envelope and optional snapshot JSON, persists/loads that snapshot,
   and preserves old direct invocation behavior. The stdio entry point is transport-agnostic:
   it reads one JSON-lines envelope per line and returns one `AuditReport` per line, with a
   `--selftest` mode. No MCP protocol is implemented (assigned to S3/A4).

## Deliberate non-goals

- No direct `EvidenceService.add` call and no `EvidenceItem` construction.
- No `GateDecision` creation or gate invocation.
- No modification of `application.py`, shared contracts, or B-owned paths.
- No live network dependency in fixtures.
- No MCP protocol implementation, HTTP transport, or remote service is included.

## Rollback boundary

The branch can be removed as one isolated task. The existing five-agent application
path is unchanged; deleting the A3 files restores the pre-A3 runtime surface.
