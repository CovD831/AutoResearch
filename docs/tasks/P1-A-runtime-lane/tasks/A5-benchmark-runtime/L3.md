## 2. 检索 adapter 的设计选择

### 2.1 为什么是三个源而不是一个

| 角色 | 源 | 依据 |
|---|---|---|
| 主选 | Semantic Scholar（免费 key） | ADR-01 §2 槽位 2 原文「Semantic Scholar API（免费 key）**主选**」 |
| 补充 | arXiv | 同一句原文「+ **arXiv 补充**」 |
| 降级轨 | OpenAlex | ADR-01 §5 原文「A5 实现加限流监控与**降级路径（OpenAlex 可选轨顶上）**」 |

ADR-01 §1 生效规则禁止成员包单方面更换首选，因此本包只**追加** ADR 已授权的两个次选源，主选槽位保持不变。

### 2.2 为什么注册为 `candidate_only`

A4 `CapabilityRegistry.invoke` 的 tier 逻辑对 `compliant_structured` 有一条 `value is None → FAILED` 分支。检索 adapter 在「合法查询、确定零命中」时正是无候选无结构化值（D-F8-01 的确定性成功终态），若注册为 `compliant_structured` 会被改写成 FAILED，直接违反 D-F8-01。`candidate_only` 既符合检索 adapter 的真实形态（只产候选），也保住空结果的成功语义。

### 2.3 结局标签映射（D-F8-01 对齐）

| provider 表现 | 标签 | 理由 |
|---|---|---|
| 2xx + 有命中 | `completed` | 正常终态 |
| 2xx + 零命中 | `completed` + 0 候选 | D-F8-01：确定性成功终态（`completed_empty` 语义） |
| 429（限流） | `failed` | 查询可证明未执行 → 已知失败，非 `unknown` |
| 4xx（非 429） | `failed` | provider 明确拒绝 |
| 5xx | `unknown` | 结局不可证（fail-closed 方向） |
| 超时 / DNS / 连接重置 | `unknown` | 与 A1 `_exception_status` 的 UNKNOWN 集合一致 |
| 缺凭据（未发请求） | `failed` | 配置失败，确定性 |
| 禁网策略 | `denied` | A4 registry 边界裁决，adapter 零调用 |

### 2.4 凭据处理

- 只从 `Settings` 读（`SEMANTIC_SCHOLAR_API_KEY` / `OPENALEX_API_KEY`），以 header 注入（S2 `x-api-key`，OpenAlex `Authorization: Bearer`）。
- 请求对象是 pydantic model 且**不含凭据字段** → 凭据无法进入 `request_fingerprint` 或 receipt。测试以序列化断言锁定。

### 2.5 限流监控（ADR-01 §5 要求的另一半）

- `rate_limit_events` / `last_retry_after_seconds` / `provider_quota` 组成进程级监控面，经 `rate_limit_summary()` 暴露。
- retry-after 提示以 diagnostic 形式随 receipt 可观测；配额计数器同样只进 diagnostics。
- 监控数据不进 fingerprint / request（测试锁定）。

### 2.6 provider 实测口径（2026-09-11，本机）

| 源 | 匿名可用性 | 实测 |
|---|---|---|
| Semantic Scholar | 搜索需 key | `GET /graph/v1/paper/search` 匿名 → 429；`/paper/{id}` 匿名通 |
| arXiv | 免 key，**当前被限流** | 成功响应 ~31s；连续调用 429；http 不通，必须 https |
| OpenAlex | 匿名可用（间歇限流） | 6 hits 级正常返回；限流时 **HTTP 200 + error body**；`X-RateLimit-*` 暴露配额 |

## 4. benchmark 运行时的设计选择

### 4.1 两种 receipt 必须分开

| receipt | 归属 | 记什么 |
|---|---|---|
| `CapabilityInvocationReceipt`（A4，已存在） | 一次 adapter 调用 | 单次能力调用的结局、可准入性、指纹 |
| `BenchmarkRunReceipt`（本包新增） | 一整轮 run | 多 case × 多 condition 的格级结果 + 预算账本 + 语料/指标 digest |

混在一起会让「一次检索失败了」和「整轮 benchmark 没跑完」变成同一件事。测试以**禁字段清单**锁定：run receipt 不含 `request_fingerprint` / `invocation_id` / `capability` 等 A4 字段。

### 4.2 两种停止条件语义不同（这是本切片的机制核心）

| 类型 | 触发 | 语义 | 可观测 |
|---|---|---|---|
| **硬**：调用数上限 / wall clock 上限 | 调用**之前** | 这次调用不允许发生 → `deny` | `calls_denied` + `stop_reason` + 该格 `CaseStatus.DENIED` |
| **软**：单次调用超时 | 调用**已发生**、结果不可信 | `interrupt`，路由 recovery | `calls_interrupted` + 该格 `CaseStatus.INTERRUPTED`；不计入 ratio 均值 |

硬停止必须在调用前判，否则预算可以被单次慢调用绕过；软停止必须在调用后判，因为「慢」这件事本身要等调用回来才知道。两处都写进 receipt，所以「为什么少了 N 格」永远可回答。

### 4.3 评估预算（冻结，写进 receipt）

`ResourceBudget`：`max_calls=240` / `single_call_timeout_seconds=20.0` / `max_wall_clock_seconds=900.0`。冻结语料三条件全跑需要 `24 × (1 + 2 + 3) = 144` 次预算调用，留 96 次余量。预算经 `BudgetView` 原样进 receipt 与报告。

### 4.4 三组「唯一变量是执法」

同一冻结语料驱动三组，`gate_off` 与 `gate_on` 的**草稿级** `hallucination_ratio` 与 `evidence_binding_rate` 必须逐位相同——检索、准入、校验在两组里都跑，差别只在拦不拦：

| 条件 | 检索 | 准入 | 校验 | 拦？ | 实测 hall | 实测 acc_hall | 实测 bind |
|---|---|---|---|---|---|---|---|
| `bare_llm` | 不发 | 无 | 不跑 | — | 1.000000 | 1.000000 | 0.000000 |
| `gate_off` | 发 | 跑 | 跑 | 不拦 | 0.145833 | 0.145833 | 0.881944 |
| `gate_on` | 发 | 跑 | 跑 | **两层都拦** | 0.145833 | **0.000000** | 0.881944 |

`gate_on` 判 `accepted` 要求确定性 gate 给 `PASS` **且** section validator 给 `VERIFIED`。语料里 case-015..017 是「gate 会 pass 但 validator 要 revise」，正是这层双层执法把 `accepted_hallucination_ratio` 压到 0 的来源。

### 4.5 语料标签与机制指标

每条 case 带 `expected_gate`（pass/revise/deny/interrupt）与 `expected_outcome`（accepted/blocked）两个标签。机制指标由标签比对算出：`true_blocks` / `false_passes` / `false_blocks` / `fail_closed_block_rate` / `mechanism_safety_score`。实测 `mechanism_safety_score = 100.0`，`gate_on` 标签零错配。

`ConditionSummary.score` 在 `scored == 0` 时为 `None` 而不是 `0.0`——不给虚假满分，并在报告 `warnings` 里点明该条件无可评分格。

### 4.6 四个注入缝

`agent` / `materials` / `admission` / `gate` 都是 Protocol，默认实现给出离线可复现路径（`RecordedAgent` / `FixtureMaterialsProvider` / `CorpusLabelAdmission` / 无 gate）。真实路径由 `RegistryMaterialsProvider`（经 A4 registry，只取 `invocation.admissible_candidates`，D-S3-01）与 `EvidenceLedgerAdmission`（唯一给材料评级的层，R005）承担。`scripts/benchmark_trust.py --live-retrieval` 切换到这个路径。

### 4.7 本切片的明确局限（写进 HANDOFF）

- **作者即评测者偏差**：语料与标签由本包自造，非外部标注集。
- **离线默认**：committed 报告用冻结语料（fixture 即材料库），不是真实检索。真实检索路径可跑（`--live-retrieval`），但结果依赖 provider 当时状态，不作晋级证据。
- **单主指标**：只冻结 `hallucination_ratio`；`evidence_binding_rate` 是报告级辅指标，不是门。
- **第四组未交付**：`docs/BENCHMARK.md` 的「gate 开 + recovery/replay」第四条件留后续包（见 D-A5-偏离-2）。
