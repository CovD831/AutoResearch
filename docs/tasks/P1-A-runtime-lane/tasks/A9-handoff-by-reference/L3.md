# A9 / S4-A5 Handoff by Reference

**Task ID**：`S4-A5-HANDOFF-BY-REFERENCE`
**Base**：`owner/a8-mainline-adapter`（A8 之上）
**裁决来源**：老板 2026-09-14 —— 问题 3 按「交接单只传引用指针」方案处置。

---

## 1. 缺陷复现（成员真实运行暴露）

真实网络检索回 44 篇论文，`PaperReaderAgent` 读完 41 张阅读卡后，构造交接单时被 pydantic 直接拒绝：

| 字段 | 上限 | 实际 | 结果 |
|---|---|---|---|
| `artifact_refs` | 20 | 41 | REJECT（`List should have at most 20 items, not 41`） |
| `evidence_ids` | 100 | 164 | REJECT |

触发点是 `agents/paper_reader.py:84-99` —— `artifact_refs` 对**每张阅读卡**铺一条并**嵌入截断后的 finding 正文**（`card.findings[0][:300]`），条目数随检索量线性增长。

### 同族检查的结果（重要）

按「修一个缺陷族必须枚举所有位置」的纪律，全仓枚举了四个 `artifact_refs` 生产者：

| 位置 | 是否随规模增长 | 处置 |
|---|---|---|
| `agents/paper_reader.py:84` | **是**（每卡一条 + 嵌入正文） | **本包修**（爆炸点） |
| `agents/paper_search.py:86` | 是，但已有硬编码 `[:20]` | **本包修**：硬编码 → 命名常量 + **可观测告警** |
| `agents/orchestrator.py:185` | 否（固定 1 条 charter） | 无需改 |
| `agents/writer.py:76` | 否（固定 1 条 manuscript） | 无需改 |

另外查得 `readiness.py:71` 只判 `artifact_refs` 是否为空，`pipeline_contracts.py:81` 另有独立字段——均不读内容。

---

## 2. 关键事实：没有任何消费方读取交接单的内容

实测全仓 `artifact_refs` / `evidence_ids` 的消费方：

- `handoffs.py` **完全不读 artifact 内容**（只有 issue/accept 的信封流转）
- 四个 agent 只**生产**不消费
- `readiness.py:71` 只用 `if not plan.artifact_refs`

**即：这些字段一直是"名单"，从未是"载荷"。** 所以"只传引用"不是能力降级，而是**让实现追上它本来的语义**。

---

## 3. 改动

1. **`contracts.py` `HandoffEnvelope`**：`artifact_refs` 20 → **500**，`evidence_ids` 100 → **2000**，并把语义写进 docstring —— 这两组数字是**引用界，不是内容界**；交接单**绝不得**用于搬运内容（`ArtifactRef.summary` 每条上限 500 字符，且信封会被持久化进 run state；批量内容属于 store，按 id 寻址）。同时保留**有限**上界，避免"放宽"变成"无界"。
2. **`agents/paper_reader.py`**：`artifact_refs` 不再嵌 `card.findings[0][:300]` / `item.statement[:300]`，只传 `artifact_id` + `kind`。
3. **`agents/paper_search.py`**：
   - 硬编码 `[:20]` → 命名常量 `HANDOFF_REF_LIMIT = 50`；
   - **顺手修掉一个同族缺陷**：`summary=paper.title` 但 `ArtifactRef.summary` 上限 500 而 `PaperRecord.title` **无长度限制** —— 超长标题会毫无理由地拒掉信封。已移除该 `summary`；
   - 截断**不再静默**：超过上限时写入 diagnostics（`handoff lists the first 50 of 57 paper records; the reader resolves the full set from state.paper_ids`），并把 `refs_attached=N` 写进 `bounded_context`。

---

## 4. 不变式

- 交接单是**引用名单**；生产者不得嵌入可读内容。
- 引用界**有限**（放宽 ≠ 无界）。
- 任何截断必须**可观测**；静默丢弃等于 fail-open。
- 不修改 `storage.py` / `evidence.py` / `gates.py` / `capability*.py` / A8 新增的 `adapter_search_service.py`。

## 5. 验证

| 项 | 结果 |
|---|---|
| 聚焦 | `pytest tests/test_handoff_by_reference.py` → **7 passed** |
| 全量 | **532 passed / 2 skipped / 0 error**（A8 后 525 + 7） |
| ruff / compileall | clean / ok |
| **判别力** | A9 改动前（A8 提交 `7b15997`，`application.py` 与 `contracts.py` 均为 A8 状态）→ **4 failed，全部判据型** |

判别力逐条（均非 ImportError）：

1. `test_envelope_accepts_a_real_retrieval_volume` —— 41/164 超界被拒（**就是成员撞到的那个崩溃**）
2. `test_bounds_are_sized_above_a_real_retrieval_run` —— 上限不足
3. `test_reader_agent_handoff_drops_inline_summaries` —— 仍嵌入正文
4. `test_paper_search_reports_when_it_truncates_the_reference_list` —— 静默截断无告警

> 判别力验证的构造说明：测试文件里的 `HANDOFF_REF_LIMIT` 导入会让基线在收集期直接 ImportError（符号缺失型，**按口径不计入证据**）。故在基线 worktree 注入了一个**只补常量、不改行为**的 shim（`HANDOFF_REF_LIMIT = 20`，与旧代码的硬编码 `[:20]` 语义一致），才取得上述 4 条**判据型**失败。
