# S3-A Capability Adapters L3

## Task source

A4（`docs/tasks/P1-A-runtime-lane/TASK-SPECS.md:46-52`）要求实现 Capability Registry 与 native/MCP/skill/plugin adapter 的统一调用边界；冻结合同为 R004-04 L2 的 CapabilityManifest / CapabilityAdapter 两节（`docs/rearchitecture/R004-trust-program/04-l2-contracts.md:5-21`）；ADR-01 slot 14（`docs/coord/adr-01-external-integrations.md:50`，2026-09-10 已落库并签字）把 MCP stdio 本体定为 L3 扩展位，本包只交付边界。

ADR-01 slot 14 对 A4 的必要条件原文：「stdio 非沙箱 → 白名单 + 显式授权 + fail-closed 必须」。本包以 `network_required` + `allowed_network_domains` + `allow_network` 默认 False + 调用前 DENIED 满足其前三项；传输层强制不在本包（无网络沙箱），见 Known limits。

## Implemented design

1. `CapabilityManifest` 补齐 L2 必备字段（`entrypoint`/`inputs`/`outputs` 可选默认、`evidence_mode` 自述、`network_required` + `allowed_network_domains` 域名白名单）；trust tier 仍由 operator 指派，不在 manifest 内。
2. `CapabilityRegistry` 注册键 = `name@version`；重复注册拒绝；`CapabilityRegistrationView` 不暴露 adapter 句柄（旁路=0 的结构保证）。
3. trust tier 两级：`candidate_only`（结果只能以 EvidenceCandidate 流出，结构化 value 丢弃；无候选即 FAILED）与 `compliant_structured`（要求类型化结果，否则 FAILED）。adapter 自述 `declared_trust_tier` 与 operator 指派不一致时忽略自述并记 diagnostic（越权=0）。
4. `CapabilityInvocationReceipt` 记录 invocation_id、capability、adapter_kind/version、trust_tier、status、**outcome_status**、request_fingerprint、candidate_count、structured_result_available、`admitted`（I3 预留，None）、diagnostics 与时间戳。
5. 网络默认禁用：`network_required` 能力在 `allow_network=False` 时于 adapter 调用前返回 DENIED receipt（零调用）；operator 显式 `allow_network=True` 才放行。域名白名单为 schema 位，传输层强制不在本包（无网络沙箱）。
6. 幂等：进程内 `(name@version, invocation_id)` 键；同 fingerprint → REPLAYED receipt 不二次调用；异 fingerprint → `CapabilityInvocationConflictError`。
7. 引用解析确定性：裸 `name` 命中多个已注册版本时抛 `CapabilityAmbiguousReferenceError`，要求改用 `name@version`；未注册引用抛 `CapabilityNotRegisteredError`。
8. `CapabilityExecutionContext` 只暴露 `emit_candidate`；`write_evidence`/`write_gate_decision` 为可见拦截（计数 + 抛 `CapabilityBoundaryViolation`），不给写路径。
9. `PaperSearchCapabilityAdapterBridge` 把 A1 `PaperSearchCapabilityAdapter` 映射进 A4 边界（状态映射 completed/completed_empty→COMPLETED、unknown_outcome→UNKNOWN、failed→FAILED、replayed→REPLAYED；桥优先读 A1 receipt 的 `outcome_status`，因此 A1 侧已重放的调用不会被二次折叠）。
10. **事实记录与准入判据分离**：`CapabilityInvocation.candidates` 是 adapter 实际 emit 内容的原始记录（失败路径同样保留），`CapabilityInvocationReceipt.candidates_admissible` 为 `computed_field`（判据 = `outcome_status == completed`，边界单点计算、不可被写错），消费方准入读 `CapabilityInvocation.admissible_candidates`。见 D-7。

### 重放语义（评审修复 R-1）

- `status=REPLAYED` 只表示「本次结果来自幂等记录、未二次调用外部」。
- `outcome_status` 承载该 invocation 的真实终态（completed / failed / unknown / denied），重放不改写它。
- 与 A1 `InvocationReceipt.outcome_status` 约定一致（`src/autoresearch/capability.py` 的重放路径保留 `outcome_status`）。
- 修复前的缺陷：receipt 无 `outcome_status` 字段，重放把 failed/denied 一律改写成 `replayed`，下游无法从 receipt 分辨真实结果（实测复现：`failed→replayed`、`denied→replayed`）。

### 候选准入语义（评审修复 R-6）

- 三层分离：**事实记录**（`candidates` / `candidate_count`，记录 adapter 实际产出，含失败路径）→ **准入判据**（`receipt.candidates_admissible`，`computed_field`，判据 = `outcome_status == completed`）→ **消费方入口**（`invocation.admissible_candidates`，仅在可准入时非空）。
- 判据必须挂在 `outcome_status` 而非 `status`：重放调用 `status=REPLAYED` 但 `outcome_status=COMPLETED`，用 `status` 判会误拒合法重放。此为 R-1 引入 `outcome_status` 之后的直接复用。
- 修复前的缺陷：两条 FAILED 路径对已 emit 候选的处理**相反**——adapter 异常路径丢弃（`candidates = [*context.candidates, *raw.candidates]` 位于 `raw = invoke(...)` 之后且同一 `try` 内，异常时该行不可达，两条 `except` 又未传 `candidates=`），契约违规路径保留。实测：`candidate_count` 分别为 0 / 1。
- 修复方向：统一为**保留原始记录**（删信息不可逆、留信息可逆；与本包「失败也要留痕」哲学一致——见边界违规路径保留 `blocked_write_attempts` 的同款做法），把安全责任交给单点准入判据，而不是靠删数据。
- 残留风险（见 Known limits）：`invocation.candidates` 仍可被下游直接读取；包内不强制消费方走 `admissible_candidates`。

## Deliberate non-goals

- 不实现 MCP 协议本体（ADR-01 slot 14：L3 扩展位，用户自带数据源时才需要）。
- 不实现 admission/补偿端到端（I3）；`admitted` 仅预留 schema 位。
- 不持久化注册表/幂等记录（A5 首个真实消费者接入时按需下沉）。
- 不接线 `application.py`，不改共享 `contracts.py`。

## Known limits

- 越权=0 是**结构保证**（不提供写路径、注册视图无 adapter 句柄），不是沙箱：adapter 为进程内对象，若其自行持有 `EvidenceService` 引用仍可绕行。本包保证的是「不给路径」，不是「不能越界」。
- 注册表与幂等记录为进程内状态；持久化按需下沉（A5）。
- **候选准入靠约定 + 单点字段，不是强制**：`invocation.candidates` 是公开原始记录，包内无法阻止下游绕过 `receipt.candidates_admissible` 直接读它做准入。本包提供的是「安全入口存在且是唯一正确读法」（R6/D-7），不是「错误读法不可能发生」。首个真实消费者（A5）接入时应在消费点落地判据。

## Rollback boundary

分支隔离：删除本包文件即恢复 pre-A4 运行时表面；`CapabilityManifest` 新字段均为可选默认，对 A1/A2 构造零影响；`CapabilityInvocationReceipt.outcome_status` 默认 None，对既有断言零影响。
