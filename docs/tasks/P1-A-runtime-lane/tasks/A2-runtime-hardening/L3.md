# A2 Runtime Hardening Task-local L3

> 本文件是 A2 的实现细节与验收记录。它遵守 R005、A1 已合并语义和 A2 任务书；实现前未决语义已按下文冻结。

## 1. 设计目标

- 在 A1 的 `RecordStore`、`PaperSearchCapabilityAdapter` 和 invocation phase 基础上增加可重复故障测试。
- 让跨进程并发更新遵守合法 phase 迁移，旧快照不能覆盖更新后的 durable record。
- 让恢复行为根据 phase 自动决定，不能由调用方随意把不确定结果标成成功或确定失败。
- 保留 A1 的 replay、fingerprint conflict、completed_empty、unknown_outcome 和 reserve-first 语义。

## 2. 建议的恢复决策表

| 当前 durable phase | 可观察事实 | A2 建议动作 |
|---|---|---|
| `reserved` | 尚未记录 service start | 收口为确定失败；不调用 connector |
| `service_started` | 可能已经产生外部副作用，但无 staged result | 收口为 `unknown_outcome`；记录 restart/recovery 原因 |
| `service_returned` | 已有 staged result，只差最终登记 | finalize staged result；不重新调用 connector |
| `finalized` | 已经存在终态 | 不重复恢复；按 replay 或显式拒绝处理 |

## 3. 结果状态与失败原因分离

业务状态继续使用：

```text
completed
completed_empty
failed
unknown_outcome
replayed
```

具体原因必须保留在 diagnostics/audit 中，例如：

```text
provider_timeout_after_service_started
process_restart_without_staged_result
deterministic_provider_rejection
staged_result_finalized
```

A2 实施前需冻结“确定失败”和“未知结果”的判定边界；默认建议是只有能够证明外部服务未执行的情况才使用 `failed`。

## 4. 故障注入点

- provider timeout：服务已开始，响应超时。
- process interruption after `reserved`。
- process interruption after `service_started`。
- process interruption after `service_returned`、finalize 前。
- evidence-before-receipt：durable facts 已写入，receipt 尚未 finalized。
- duplicate submission：相同 identity/fingerprint 重复提交。
- conflicting fingerprint：相同 identity 使用不同请求。
- cross-process stale writer：两个独立 `RecordStore` 实例用旧 phase 写入同一条记录。

所有注入器必须使用 fake connector、本地 SQLite 和确定的 scenario id，不依赖网络或外部 API。

## 5. 并发状态迁移原则

- 进程内 `_lock` 只作为本进程线程保护，不能作为跨进程正确性的依据。
- phase/state 更新必须带预期旧状态条件；更新行数为零时视为 stale writer，重新读取并禁止覆盖。
- finalized 记录不能被任何旧 pending 快照覆盖回 pending。
- 多进程测试必须检查最终状态、receipt、audit events 和 durable facts 数量。

## 6. 诊断矩阵字段

每个场景报告至少记录：

- `scenario_id`
- `request_fingerprint`
- `initial_state` / `initial_phase`
- `fault_point`
- `recovery_action`
- `receipt.status` / `receipt.outcome_status`
- `diagnostics`
- papers/evidence/wiki/idempotency/audit durable facts before/after
- `connector_calls`
- `passed`

## 7. 预计交付路径

- Runtime 修复：`src/autoresearch/storage.py`、`src/autoresearch/capability.py`，必要时才调整 invocation contracts。
- 常规回归：`tests/test_runtime_hardening.py` 和相关 recovery/storage 测试。
- fixture：`tests/fixtures/paper_search/` 或 A2 专用 fixture 目录。
- 可运行证据：`docs/rearchitecture/worktrees/A-runtime-hardening/`。
- task-local 记录：本目录的 `TASK.md`、`PROGRESS.md`、`HANDOFF.md`。

## 8. 已冻结的实现决定

- failure cause 继续使用 diagnostics/audit 保存，不新增第二套结构化状态字段；报告同时暴露 diagnostics 和 side-effect count。
- `TimeoutError`、`ConnectionError`、`OSError`、`UnknownProviderError` 按 unknown_outcome 处理；A1 已冻结的普通 provider RuntimeError 继续按 failed 处理，并保留异常类型和消息。
- A1 回归测试、A2 专项 pytest 和 fault matrix 均通过，确认 F-3 收窄没有破坏已确认的 provider failure 语义。
- 不允许通过直接修改数据库来代替 recovery API 的测试。
