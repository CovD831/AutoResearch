### 2.4 实现决策（开工后补 —— 实际怎么落地）

| 决策 | 选择 | 理由 |
|---|---|---|
| 必填字段的编码 | 除 `run_id` / `created_at` 外，全部 ✅ 字段**无默认值**（必须显式传），**含 `output_hashes`**（未产出时显式传 `{}`） | K1 表把 `output_hashes` 标为 ✅ 且「未产出时 `{}`，不得填假值」。「显式传 `{}`」与 K1-2 的「不得省略 seed」是同一纪律：**省略不得成为合法路径**，否则「没记录」与「没产出」不可区分 |
| `created_at` 带默认值 | `Field(default_factory=utc_now)` | 任务卡明文「`utc_now()` 用于 `created_at` 默认值」；K1 表标 ✅ 指的是「字段恒存在」，默认值即恒存在，不是「调用方必须手写」 |
| K1-1 落地 | `@field_validator("command", mode="before")` 拒绝 `str`；字段类型同时保持 `list[str]` | **双防线**。实测（pydantic 2.13.4）：类型层单独就能拒 `str`（不会把 `str` 协变成 `list`）。validator 的独有贡献是 (a) 与规则同名的显式报错，(b) 不依赖字段声明——突变 M1 把类型放宽为 `str \| list[str]` 后，只剩 validator 能拦（§6） |
| K1-2 落地 | `seeds: list[int] = Field(min_length=1)` | 声明式等价于「`len == 0` → 拒绝」；且无默认值可回退 |
| K1-3 写侧落地 | `exit_code: int \| None = None` + `mode="before"` 守卫：`None` **显式保持为 `None`**；`bool` / `str` 拒绝 | 见 §9 **D-1**（实测 pydantic 会把 `False → 0`、`"0" → 0`） |
| K1-3 读侧落地 | `@property executed`（派生，**不是字段**，不入 schema、不进 `model_dump()`） | K1-3 的「⟺」需要一个可断言的读侧接口：否则 N-4 只能断言「字段非 None」，无法断言「**没有被当作未运行**」 |
| K1-4 落地 | **零 validator**；模块 docstring + 字段注释显式标注「架构意图、不可机械校验、交 M08-07」；测试只有一条「断言不存在 validator」的反向守卫 | 见 §9 **D-5** |
| 引用复用的调用点 | `new_id` → `run_id` 默认工厂；`utc_now` → `created_at` 默认工厂；`WorkPackage` → `for_work_package()`；`ArtifactRef` → `output_refs()` | §2.3 判据：API 名必须出现在代码里。四个调用点的证据见 §6.4 |

### 2.5 契约硬化条款（**owner 2026-09-15 裁决：D-1 / D-2 均保留**）

> **来源**：owner 2026-09-15 亲自复核本包交付后裁决 —— **D-1 与 D-2 保留，作为 K1 的正式硬化条款**。
> 措辞自此由「强化项（可回退的实验性收紧）」改为「**契约硬化**」。

| 条款 | 硬化内容 | 裁决理由（owner 原文口径） |
|---|---|---|
| **D-1** | `exit_code` 输入域：`None` 保持；`bool` / `str` 拒绝 | **不是「更安全」，是补掉一个真实的坍缩通道**：pydantic 2.13.4 lax 模式把 `False → 0`，`exit_code=False` 会被存成**执行成功**。回退它等于**让 K1 在自己的核心不变量上留一个洞** |
| **D-2** | `model_config = ConfigDict(extra="forbid")` | 未知字段静默丢弃与本项目缺陷族同源（「把未知记成正常值」的下游形态）：`seed=0` 拼错 → 变成「没提供 seed」，而这个错误**不可观测** |

**性质**：两条都只**拒绝非法输入**，不放行、不改写任何契约合法输入（13 字段与 4 条不变量对 K1 **零偏离**）。
**可逆性信息保留**（供将来 owner 复核用，非当前建议）：D-1 回退 = 删 `_exit_code_semantics`；D-2 回退 = 删一行 `model_config`。
**测试覆盖**：D-1 → `test_exit_code_rejects_bools_*` / `test_exit_code_rejects_strings_*`；D-2 → `test_an_unknown_field_is_rejected_instead_of_silently_dropped`。
**移交提示**：**M08-03 的 K2 `ExecutionResult.exit_code`（L2 已冻结为 `int \| None`）应复用 D-1 的同一守卫**，否则同一坍缩通道会在那里重开（遗留 R-6）。

本包至少 4 条负例：

| # | 负例 | 断言什么 |
|---|---|---|
| **N-1** | `command="python train.py"`（字符串） | **被拒**（不是被 split，不是静默通过） |
| **N-2** | `seeds=[]` | **被拒**；且 `seeds=[0]` 显式无随机性时**通过** |
| **N-3** | 未执行态：`exit_code=None` | **通过**且 `exit_code is None`；

## 6. 判别力证据（**收口必填**）

新测试必须在**修复前/实现前基线**上确实失败，且区分：

- **判据型失败**（断言被违反、异常语义正确）→ **计入证据**
- **符号缺失型失败**（`ImportError` / `AttributeError: no attribute`）→ **不计入证据**

> 本项目口径（`docs/process/DISCRIMINATING-POWER.md`）：
> **判据型失败计入证据，符号缺失型不计入。**
> 实测前例：O12 第一轮 16 例中 12 例判据型；第二轮 28 例中 21 例判据型。
> 新模块的 validator 测试若只报 `ImportError`，**必须注入「只补符号、不改行为」的 shim** 才能取得判据型。

### 6.3 结论（**负向优先**）

1. **真基线拿不到判据型证据 —— 如实标注。** P0 只有 `1 error: ModuleNotFoundError: No module named 'autoresearch.run_manifest'`，整个测试文件在 collection 期就死，**一条断言都没跑** ⇒ 按口径 **计入 0 例**。这正是本节约定的「必须注入 shim」的原因。
2. **P1（只补符号）**：N-1 / N-2 取得判据型（`DID NOT RAISE`）；**N-3 / N-4 是符号缺失型**（`AttributeError: 'RunManifest' object has no attribute 'executed'`，因为 shim 没有 helper/property）⇒ **不计入**。
3. **N-1 的 P1 判据型必须人工判回一部分。** P1 下 N-1 的失败是 `assert 'argv' in "1 validation error ... Input should be a valid list"` —— 即 shim **已经拒绝了字符串**（靠 `list[str]` 类型声明），只是报错文案里没有 `argv`。按 `DISCRIMINATING-POWER.md` 的「shim 污染分类」条款，**N-1 的承重证据不能记在 P1 上**，应记在 **M1**：只有把类型放宽 + 关掉守卫之后，字符串才真的被接受（`DID NOT RAISE`，判据型）。
   → 顺带结论：**K1-1 的「拒绝」不只靠 validator，类型声明也在拦**；validator 的独有贡献是「与规则同名的显式报错」和「不依赖字段声明的独立性」。
4. **承重证据 = M1–M4 四个突变探针**（对角矩阵，判据型 16/16）：每个负例都精确指向它要挡的那个实现缺陷，且**不影响其余 34–38 条测试**（唯一附带效应：M3 同时杀掉 `test_a_fully_populated_manifest_validates_and_survives_a_json_round_trip` —— 同一处 `None → 0` 坍缩也会让 JSON round-trip 的相等断言失败，属预期）。
5. **N-3 的实测语义**：M3 下 `assert 0 is None` / `assert 0 != 0` 失败；M4 下 `assert None == 1` 失败 —— 两条负例分别从「未执行被写成 0」与「失败被写成未执行」两个方向封住了该缺陷族。
6. **无 shim 伪装成判据型的用例**：P1 的 `criterion` 里，除 N-1（已判回）外，其余（N-2、bool / str / 未知字段等 D-1/D-2 硬化项）均因 `DID NOT RAISE` 失败，属真实判据型。

> 即「**没有任何人假装校验过 K1-4**」。**在有人给 `output_hashes` 加一个只能比字符串的假校验时，它会变红**；
> 它**不是**一条在「hash 是否真实」上永远为绿的通过断言 —— 后者才是本项目禁止的恒真假绿。
> K1-4 的真实性校验**没有**、也**不可能**由 K1 承担，**承接方是 M08-07 的闭环 Gate**（它才拿得到真实产物文件）。

- 断言原文见 `tests/test_run_manifest.py` 末节；它可被违反 ⇒ 非恒真。
- 与之一体两面的纪律：本测试文件里**没有任何**关于「hash 内容是否真实 / 是否对应真实产物」的断言。
  为免误读，如实列出唯一触及 `output_hashes` 的通过断言：`test_output_refs_of_a_run_that_produced_nothing_is_empty_not_a_placeholder`
  断言「显式传入 `{}` 时字段原样为 `{}`、`output_refs()` 为空」—— 这是**字段管道语义**（不得凭空造占位符），
  与 K1-4 的真实性无关，且可被违反（若有人给该字段塞默认占位符即变红）。
