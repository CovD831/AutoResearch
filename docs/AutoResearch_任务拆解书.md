# AutoResearch 模块拆解书

> 版本：`AR-003 / 2026-08-22`
> 当前粒度：模块级。先按模块分配负责人，模块负责人再决定何时继续拆子任务。
> 详细版暂存于 [AutoResearch_任务拆解书_详细版.md](AutoResearch_任务拆解书_详细版.md)，不作为当前分配入口。

## 1. 分配原则

每个模块只分配给一个主负责人，负责人可以再组织多人协作。模块负责人需要维护：

- 模块目标和边界；
- 对外接口或交付物；
- 上游依赖和下游使用者；
- 模块级验收标准；
- 风险、阻塞和 evidence ID。

当前不要求一次性拆到函数、接口或工单。模块完成后，再根据实际工作量拆成子任务。

状态说明：

- **基础已落地**：已有 foundation 代码和本地证据，但不代表生产级或真实论文质量。
- **部分落地**：已有骨架，仍缺关键能力或严格验收。
- **待开发**：已纳入范围，尚未形成可验收实现。
- **外部阻塞**：需要真实 idea、语料许可、实验资源或部署决策。

## 3. 推荐执行顺序

| 阶段 | 模块 | 阶段结果 |
|---|---|---|
| 第一阶段：治理和底座 | M00–M04 | 仓库、合同、证据、门禁、状态机和规范存储稳定 |
| 第二阶段：文献闭环 | M05–M07 | 论文可检索、可阅读、可追问，创新候选有证据边界 |
| 第三阶段：研究和论文 | M08–M10 | 工作包可执行，结果可追溯，稿件可审核和打回 |
| 第四阶段：知识和入口 | M11–M15 | 分库检索、画像、经验、自进化、API/UI、运维安全完善 |
| 第五阶段：真实验收 | M16 | 一个真实论文项目完成可复核 Pilot，不外推结论 |
| 第六阶段：生产化 | M17 | 根据实际部署规模完成数据库、并发、成本、灾备和发布 Gate |

并行建议：M00–M02 可先并行；M03/M04 在合同稳定后并行；M05/M06/M07 必须按文献链路推进；M08–M10 依赖真实证据；M16 需要用户提供项目参数；M17 不应早于 Pilot。

## 5. 当前首批分配建议

先只分配以下模块负责人，不再拆更细：

1. **底座负责人**：M01–M04，负责合同、证据、门禁、状态和存储。
2. **文献负责人**：M05–M07，负责检索、阅读、陪读和创新分析。
3. **研究执行负责人**：M08，负责 WorkPackage、RunManifest 和结果验证。
4. **论文交付负责人**：M09–M10，负责写作、修改、引用和审核。
5. **知识平台负责人**：M11–M12，负责 Wiki+Graph、画像、经验和自进化。
6. **平台运维负责人**：M00、M13–M15、M17，负责入口、安全、运维、部署和发布。
7. **项目负责人**：M16，负责真实 idea、语料、实验边界和 Pilot 验收。

模块负责人到位后，再为每个模块建立独立任务文件；模块之间只通过合同、artifact、evidence ID 和验收状态交接，不转发整段上下文。
