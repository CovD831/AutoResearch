## Invariants

- `wiki_page` 是版本记录；裸 `page_id` 只能经 `wiki_page_head` 和 `get_page()` 解析。
- WikiPage revision 与 head 必须在同一事务写入，旧 revision 不得覆盖。
- Evidence 继续使用独立 `kind="evidence"`，不得混入 Wiki 检索结果。
- 跨分区边只能使用受管桥接类型；同分区限定类型不得跨分区；未知关系不得绕过边界。
- `list_pages()` 的数据库查询次数必须为常数，而不是每个 head 再查询一次。
- 不改 `KnowledgeService.retrieve()` 输入签名，不删除或改名 `RetrievalHit` 既有字段。
- 不修改任务包列出的 frozen/forbidden 路径，除非先取得新的 owner 裁决。
- 不实现本包明确排除的向量检索、融合排序、Statement、ContextPack 和生产图数据库。

## Decisions

- D-M11-01: Do not repeat P1's append-only writer/head implementation; treat it as inherited behavior
  and add only missing M11 evidence and regression coverage.
- D-M11-02: Classify full revision-ID reads separately from forbidden bare-ID reads. The remaining
  `list_pages()` per-head read is an N+1 performance defect, not a head-resolution violation.
- D-M11-03: Keep the old A7 vector prototype outside this package. Its backup is historical input only;
  M11-MVP-01 explicitly excludes vector retrieval and ranking.
- D-M11-04: Use one storage-level JOIN rather than a generic two-query batch API. The join directly
  maps each `wiki_page_head.current_revision_id` to its `wiki_page.record_id`, keeps query count at one,
  and naturally omits dangling heads without changing `KnowledgeService.list_pages()`'s public contract.
- D-M11-05: Keep `GraphEdge.relation` typed as `GraphEdgeKind`. The registry classifies typed core
  relations and can be injected/extended without changing `add_edge()`; arbitrary strings remain
  fail-closed. This follows the source design's "core enum first, registry interface reserved" boundary.
- D-M11-06: Treat `GraphEdge.partition` as the source page's partition. A bridge edge may point to a
  target in another partition, but it cannot be stored under an unrelated third partition.
- D-M11-07: The `contracts.py` additions satisfy conditional-path rule B: the required failing cases
  prove that the existing relation contract was incomplete, and the change only adds the eight task-
  mandated enum values plus their bridge classification.
- D-M11-08: Enforce contiguous revisions exactly. A missing first r1, a skipped revision, a repeated
  revision, or a lower revision is rejected instead of being silently accepted or renumbered.
- D-M11-09: Acquire SQLite's write reservation before reading the head (`BEGIN IMMEDIATE`), then hold
  it through version insert and head update. Python's per-instance lock alone is insufficient because
  independent stores/processes do not share it.
- D-M11-10: Use strict INSERT for immutable WikiPage revision rows while retaining upsert for the
  mutable head pointer. An orphan version without a head is treated as corruption and is not adopted
  or overwritten by `add_page()`.
- D-M11-11: Configure persistent WAL mode during `RecordStore` initialization rather than on every
  connection. Concurrent cold starts retry only lock-related `OperationalError` failures within a
  bounded window, preventing one startup from failing while another connection negotiates WAL.
- D-M11-12: Use one frozen cross-object input fixture with separate isolation and repeatability tests.
  The expected result is hand-authored and never regenerated from the implementation, so a behavior
  change cannot silently bless itself; separate test names retain failure localization.
- D-M11-13: Treat source convergence as a mechanical gate rather than another narrative review. Every
  source clause now has its own matrix row or an explicit shared row, including structural/prohibition
  clauses that ordinary runtime scenarios cannot expose.
